# My Video App 1.19.0 · Windows 앱

**Windows 10/11 x64용 개인용 다운로드 앱입니다.** YouTube 다운로드는 이 데스크톱 앱에서 사용합니다. Chrome 확장에는 YouTube 기능이 없습니다.

## 실행과 첫 다운로드

1. `my-video-app-desktop-windows-x64.zip`을 내려받아 **폴더 전체를 압축 해제**합니다. ZIP 안에서 실행하거나 EXE만 다른 폴더로 옮기지 마세요.
2. `MyVideoApp` 폴더의 **My Video App.exe**를 실행합니다.
3. 처음 다운로드할 때 **저장 폴더를 선택**합니다. 이후 파일마다 다른 이름으로 저장하는 창 없이 해당 폴더에 자동 저장합니다. 위치는 **설정 → 다운로드 폴더**에서 변경합니다.
4. YouTube 영상 주소 또는 직접 미디어 주소를 붙여 넣고 화질·형식을 고른 뒤 **다운로드 추가**를 누릅니다.
5. 대기열에서 진행률·속도·남은 시간을 확인하고, 완료되면 **폴더 열기**로 결과를 확인합니다.

Python·yt-dlp·EJS·Deno·FFmpeg·Qt가 포함되어 있어 별도 Python 설치, Chrome 도우미 등록, 확장 ID, API 키가 필요하지 않습니다. 설치·등록 없이 폴더에서 실행하는 포터블 앱이며 실제 영상 다운로드에는 인터넷이 필요합니다. 추가 런타임을 포함하므로 확장 ZIP보다 큽니다.

## 기능과 범위

| 기능 | 동작 |
| --- | --- |
| YouTube 다운로드 | 공개 단일 VOD·Shorts를 yt-dlp로 처리. 로그인·유료 권한·DRM을 우회하지 않음 |
| 화질·저장 형식 | 제공된 최고 화질 또는 선택 해상도, 원본·MP4·WebM·MKV·MP3·M4A. 영상과 음성은 FFmpeg로 병합 |
| 대용량 영상 | 길이 제한 없이 다운로드하며 저장 공간·사이트 제공 조건의 영향을 받음 |
| 대기열 | 자동 2~4개 또는 1~16개 동시 작업, 사이트별 1~16개 설정, 취소·오류·재시도, 완료 파일의 폴더 열기 |
| 전송 가속 | 검증 가능한 대용량 직접 파일의 최대 4개 분할 전송, HTTP/3 우선 연결과 HTTP/2·HTTP/1.1 폴백 |
| 기록·설정 | 사용자 계정의 내장 SQLite DB에 자동 저장. 기록을 지워도 다운로드한 파일은 유지 |
| 화면 | 밝은/어두운 테마, 키보드 조작, 긴 제목 정리, 기록 검색·상태 필터 |
| 보안 검사 | 설정에서 다운로드 후 Windows 보안 검사를 선택. 검사 불가·실패는 안전함으로 표시하지 않음 |

지원하지 않는 기능: 재생목록 일괄 다운로드, 라이브 녹화, DRM 해제, 로그인·구독 우회, 브라우저 쿠키 자동 추출. 사이트 변경·접근 조건·영상 제공 형식에 따라 일부 요청은 실패할 수 있습니다.

## 동시 다운로드 설정

**설정 → 동시 다운로드**에서 자동 또는 1~16개를 선택합니다. 자동은 논리 CPU 수를 기준으로 2~4개를 선택하는 기본값이며, 인터넷 속도를 측정하는 기능은 아닙니다. 기존에 1개·2개로 저장한 설정은 유지합니다.

**같은 사이트 동시 다운로드**는 기본 4개입니다. 한 사이트의 영상 8개를 함께 진행하려면 전체 동시 다운로드와 같은 사이트 설정을 모두 8개 이상으로 지정하세요. YouTube의 시청·공유 주소는 같은 사이트로 묶습니다. 사이트 구분은 입력한 원본 주소를 기준으로 하므로 CDN 리디렉션의 실제 연결 제한과는 다릅니다.

대기열에서는 실행 수가 적은 사이트를 먼저 배정하고, 같은 조건에서는 먼저 추가한 작업부터 시작합니다. 같은 사이트가 제한에 도달해도 다른 사이트의 작업은 시작할 수 있습니다. 값을 늘리면 대기 중인 작업을 추가로 시작하고, 줄이면 진행 중인 작업을 유지하면서 완료 후 새 제한에 맞춥니다.

전송 작업과 조각 다운로드 수를 함께 늘리지 않도록 조각 예산은 전체 16개로 제한합니다. 영상 분석은 최대 2개, 미디어 처리 최대 2개, 백신 검사 최대 1개가 함께 실행되며 자원을 기다리는 상태를 표시합니다. 같은 단계의 반복 진행률 알림은 작업당 약 100ms 간격으로 줄이고 단계 변경과 완료 알림은 바로 표시합니다.

작업 수를 늘리면 서버 제한, 회선 포화, 디스크 쓰기 때문에 개별 파일이 느려질 수 있습니다. **우선 4개로 사용하고 여유가 있으면 늘리는 것을 권장합니다.**

## 전송 가속과 HTTP/3

**설정 → 파일별 병렬 다운로드**, **HTTP/3 우선 연결**은 기본 ON입니다. 동시 작업 수와 별도로 큰 파일 하나를 최대 4개 요청으로 나눠 받을 수 있습니다. 모든 파일이 공유하는 전송 예산은 16개이므로 전체 연결 수를 무제한 늘리지 않습니다. 서버·회선·디스크가 포화되면 작업 수를 줄이는 편이 나을 수 있습니다.

분할 전송은 8MiB 이상이고 서버가 정확한 바이트 범위와 강한 ETag 식별값을 제공할 때 사용합니다. 각 조각의 범위·전체 크기·식별값을 확인한 뒤 디스크의 정확한 위치에 기록합니다. 조건이 맞지 않으면 저장 전에 단일 전송으로 전환하고, 전송 중 원본이 바뀌면 서로 다른 데이터를 섞지 않고 실패로 처리합니다. 전체 파일을 메모리에 올리지 않습니다.

공개 YouTube 영상에서 추출한 직접 미디어 주소와 일반 HTTP(S) 직접 파일에 새 전송 경로를 적용합니다. HLS/DASH 조각과 기존에 이어받던 일부 YouTube 작업은 기존 yt-dlp 경로를 유지합니다. 따라서 **모든 다운로드가 HTTP/3를 사용하는 것은 아닙니다.** 서버와 UDP·프록시 경로가 허용할 때 HTTP/3를 시도하며 연결할 수 없으면 HTTP/2 또는 HTTP/1.1로 폴백합니다. HTTPS 주소나 Alt-Svc만 보고 HTTP/3라고 표시하지 않고 실제 협상 결과만 표시합니다.

인증서 검증과 상속된 프록시 설정을 유지합니다. 브라우저 프로필·쿠키·인증 헤더를 추출하거나 보호 설정을 끄지 않습니다. 일시적인 네트워크 오류와 짧은 서버 대기는 제한 횟수만 재시도하며, 대기 중에도 취소할 수 있습니다.

## 다운로드 속도 제한

**설정 → 다운로드 속도 제한**에서 ON/OFF와 앱 전체 합계 상한을 지정합니다. 기본값은 **OFF**이며, OFF에서는 앱의 대역폭 상한을 적용하지 않습니다. ON일 때 입력한 값은 여러 파일·분할 요청·기존 yt-dlp 전송이 함께 공유합니다. 다운로드 중에 바꿔도 반영되며 OFF로 전환하면 제한 대기를 해제합니다.

단위는 **KiB/s**이며 64~1,048,576KiB/s를 지정할 수 있습니다. 저장된 기본 상한은 10,240KiB/s(10MiB/s)입니다. 제한기는 앱이 처리하는 미디어 바이트를 기준으로 하며 순간적으로 최대 64KiB의 버스트를 허용합니다. TLS·헤더·커널 버퍼까지 포함한 물리 회선 속도의 정확한 측정기는 아닙니다.

서명되지 않은 개인용 Windows 빌드입니다. 이 패키지에서 인증서·백신·OS 보호 설정을 변경하지 않습니다. 포함된 구성 요소의 고지와 소스 위치는 `licenses`와 `THIRD_PARTY_NOTICES.md`를 참고하세요.

## 데이터와 삭제

다운로드 파일은 사용자가 고른 폴더에 저장합니다. 기록·설정은 `%LOCALAPPDATA%\MyVideoApp\Desktop` 아래의 SQLite DB에서 관리합니다. 앱 폴더를 삭제해 프로그램을 제거할 수 있으며, 기록·설정도 지우려면 앱을 종료한 뒤 해당 사용자 데이터 폴더를 별도로 삭제합니다.

현재 변경과 신규 검사 범위는 저장소의 `reports/DESKTOP_1_19.ko.md`에 기록합니다. 이전 검사는 다시 실행하지 않습니다. 실제 YouTube 사이트 접근과 Windows 사용자 환경은 사이트·OS 조건에 따라 추가 확인이 필요합니다.
