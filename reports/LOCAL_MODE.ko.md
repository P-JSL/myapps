# My Video App 개인용 로컬 모드

현재 버전은 1.2.0이다. 새 도구의 자세한 사용법은 `FEATURES.ko.md`를 참고한다.

버전 1.1.0부터 설치본은 독립 TypeScript 엔진을 사용한다. 원본 다운로드 서비스,
구독·활성화·프리미엄 화면, 원격 규칙·광고·진단 전송·환영 페이지를 포함하지 않는다.
원본 라이선스 확인을 성공으로 위조하거나 기존 유료 기능을 활성화하지 않는다.
앱 자체 계정/구독/인증 서버가 없으며 기능 사용 횟수를 과금 기준으로 제한하지 않는다.
FFmpeg 등의 저작권·오픈소스 라이선스 고지는 보존한다.

## 지원 기능

- 페이지 video/audio/source/직접 미디어 링크와 응답 Content-Type으로 미디어를 감지한다.
- HTTP(S) 영상/오디오 파일은 브라우저 다운로드 API로 저장한다. 주소 직접 입력도 지원한다.
- 암호화되지 않은 HLS VOD의 미디어/마스터 목록, 외부 오디오, 초기화 조각, 바이트 범위를 처리한다.
- 정적 단일 Period DASH의 SegmentTemplate/SegmentTimeline/SegmentList/BaseURL 트랙을 처리한다.
- HLS/DASH는 로컬 FFmpeg Wasm에서 코덱을 복사하여 MP4로 묶는다.
- 기록은 이 브라우저의 확장 저장소에만 보관한다. 기록 삭제는 다운로드 파일을 삭제하지 않는다.
- 취소, 저장 폴더 열기, 다운로드 완료 후 선택적 업스케일링, 이미지/영상 2x·4x 확대를 제공한다.
- HLS/DASH의 최고화질/제공 해상도 상한을 선택하고, 일반 파일·스트림을 MP3/M4A로 저장한다.
- 로컬 파일을 MP4/WebM/MKV 영상 또는 MP3/M4A/WAV 음성으로 변환한다.
- 별도 영상·음성 파일을 MP4/MKV로 병합한다. 원본은 보존하고 결과를 별도로 저장한다.

## 통신과 인증

다운로드할 때 사용자가 선택한 미디어 사이트에 접속한다. 파일·스트림은 해당 사이트의
정상적인 접근 권한과 브라우저 세션을 따른다. 앱의 별도 로그인은 없다. 사이트 로그인,
만료된 서명 주소, 지역/접근 제한을 우회하지 않는다. 자동 미디어 수집 자체는 추가
요청을 하지 않으며, 파일/목록 가져오기는 사용자가 다운로드를 선택한 후에 시작한다.

원격 제품 서버·계정 서버·분석 서버로 데이터를 보내지 않는다. 일반 파일의 임시 준비가
실패하거나 파일이 크면 브라우저의 원래 직접 다운로드 경로를 사용한다. 이 경우
자동 업스케일링용 복사본을 제공하지 못할 수 있으며 저장된 파일을 직접 선택하면 된다.

## 한계

원본과 모든 사이트/기능이 동일한 제품은 아니다. 원본 사이트별 전용 추출기,
YouTube 전용 서명 처리, DRM/암호화 스트림, 라이브 녹화, 여러 Period DASH,
자막/첨부 메타데이터 전체 보존은 지원 범위가 아니다. 영상 사이트의 공개 MP4 또는
지원하는 비암호화 목록이 브라우저에 나타나는 경우만 감지/다운로드한다.

스트림은 최대 4,096조각·입력 128MiB·약 128MiB 미만 출력·5분 준비 한도를 적용한다.
동시 준비/다운로드는 최대 8개이며 진행 중인 같은 주소의 중복 요청을 방지한다.
일반 대용량 직접 파일은 브라우저 다운로드 경로를 사용한다. 임시 업스케일링 복사본은
파일당 256MiB·총 512MiB·4개·24시간(다음 사용 시 정리)이다. 영상 업스케일링은
최대 10분·결과 16,777,216픽셀·한 변 8,192·5분 실행 한도가 있다.
로컬 변환·병합도 입력/출력 각각 256MiB, 길이 10분·실행 5분 한도이다. 병합은 두
입력의 크기를 합산하고 짧은 트랙 길이까지 저장한다. MP3/M4A 다운로드는 128MiB
입력 한도를 적용한다. 화질 메뉴는 제공된 트랙 중 선택하며 화질 복원이나 모든
사이트의 전용 추출기를 제공하는 것이 아니다. WebM 변환은 VP8/Opus를 사용한다.

원본 공개 manifest key를 사용하지 않으므로 이전 버전과 확장 ID/기록 저장소가 다르다.
이전 원본 엔진·전용 추출기·계정 코드는 현재 프로젝트와 설치 ZIP에서 제거했다.
이전 구현과 원본 파일은 Git 이력의 `806ef92` 및 최초 업로드 자료에서 확인할 수 있다.
클라우드의 관리자 정책 때문에 실제 unpacked 확장 설치/Chrome API 통합 검증은
차단되어 있으며, 브라우저 하네스의 Chrome API 부분은 테스트 대역이다.
