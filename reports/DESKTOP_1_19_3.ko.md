# 1.19.3 Windows 앱 HTTP/3 제거

**요청에 따라 Windows 앱의 HTTP/3 연결과 설정만 제거했습니다.** 병렬 다운로드, 동시 작업 수, 속도 제한, 취소·재시도·이어받기, 영상·음성 병합, 백신과 실행 로그 기능은 유지합니다.

## 첨부 로그에서 확인한 내용

제공된 로그에는 정보 기록 67개가 있고 오류나 종료 기록은 없습니다. 영상 트랙은 약 91.6초에 완료됐으며, 뒤이어 오디오 트랙이 HTTP/3 단일 연결로 전송됐습니다. 오디오 구간의 약 160초 동안 다운로드 진행은 약 4.7MiB 늘었고 기록된 속도는 약 30KiB/s였습니다.

이 기록은 HTTP/3 오디오 전송이 느렸다는 근거입니다. 같은 서버·파일의 HTTP/2 비교 자료는 없으므로, 프로토콜 구현과 서버별 속도 제한 중 어느 것이 원인인지까지 단정하지 않습니다. 이번 패치는 해당 HTTP/3 경로를 제거합니다. 실제 사이트에서의 속도 향상을 측정했다는 의미는 아닙니다. 첨부 로그 원문은 저장소나 설치 ZIP에 포함하지 않습니다.

## 변경 범위

| 항목 | 1.19.3 동작 |
| --- | --- |
| 직접 미디어 연결 | HTTP/2를 허용하는 TCP/TLS 옵션 사용. 서버가 HTTP/2를 제공하지 않으면 HTTP/1.1 |
| HTTP/3 설정 | 화면·엔진·전송 옵션에서 제거. 기존 DB의 해당 설정만 자동 정리 |
| 병렬·속도 제한 | 기존 분할 검증, 전체 전송 예산, 다운로드 속도 제한 ON/OFF 유지 |
| 다운로드·보안 | 기존 영상 재사용, 오류 복구, 취소, 병합·검사 유지 |
| 이력·기타 설정 | 다운로드 기록과 나머지 설정 유지. 예전에 저장한 HTTP/3 로그도 계속 조회 |
| Chrome 확장 | 버전 표기만 갱신. 이 패치는 Windows 앱의 전송 경로에 적용 |

TLS 인증서 검증·상속 프록시·헤더 제한과 고정 런타임·라이선스 고지는 유지합니다. 다른 구성 요소를 갱신하거나 다운로드 알고리즘의 동시성·버퍼·재시도 수를 함께 바꾸지 않습니다.

## 검사·배포 범위

**이전에 수행한 검사는 모두 건너뜁니다.** 새 검사에서 HTTP/3 요청 옵션 제거, HTTP/2·HTTP/1.1 선택 및 표시, 기존 HTTP/3 설정의 재활성화 차단, 나머지 설정·기록 유지와 릴리스 증거 연결을 확인합니다. Windows 빌드는 내장 libcurl로 새 HTTP/1.1 루프백 전송도 확인해야 게시됩니다.

로컬에서는 새 전송·설정 검사 9개, GUI 검사 8개, 배포 범위 검사 16개, 총 33개가 통과했습니다. Windows에서는 같은 범위에 실제 내장 백엔드 HTTP/1.1 검사 1개를 추가한 총 34개가 통과해야 합니다. 기존 전체 검사는 반복하지 않습니다.

첫 Windows 실행에서 전송 10개(실제 HTTP/1.1 포함)와 배포 16개는 통과했습니다. GUI의 폴더 비교 한 개가 동일한 폴더의 Windows 8.3 단축 경로와 정식 경로를 문자열로 비교해 실패했습니다. 해당 검사만 `Path.samefile()`로 실제 폴더 동일성을 비교하도록 고쳤고, 수정한 검사 한 개만 로컬에서 다시 통과했습니다. 앱 코드와 데스크톱 ZIP은 바뀌지 않았으며 소스 ZIP만 갱신합니다. 새 Windows 실행의 결과는 최종 Release 증거를 기준으로 합니다.

로컬의 옵션 검사는 통제된 네이티브 백엔드를 사용하고, GUI는 개발용 Qt로 실행합니다. 실제 YouTube 속도 비교·이전 전체 전송·HTTP/3·로그·GUI·백신 검사를 다시 수행한 결과가 아닙니다. 빌드 입력 해시 확인과 현재 소스/ZIP 일치 확인은 패키징 과정에서 유지합니다.

현재 소스·검사·빌드는 `release-validation.json`, 실제 Windows 실행 결과는 Release의 `WINDOWS-VALIDATION.json`에 연결합니다. ZIP 전체를 갱신한 뒤 실행하세요. 기존 작업을 이어 받으려면 임시 폴더와 기록을 지우지 말고 **다운로드 기록 → 다시 시도**를 사용하세요.
