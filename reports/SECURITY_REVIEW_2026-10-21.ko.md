# My Video App 1.11.0 보안·전체 코드 검토

검토 기준일은 2026-10-21이다. 런타임·네이티브 백신·미디어 처리·팝업·배포 구조를 병렬 검토하고 별도 에이전트가 수정과 검증 근거를 다시 확인했다. 알려진 취약점 목록 조회, 재현된 앱 오류 수정, 공격 경로 완화와 아직 패치하지 못한 엔진 문제를 구분한다.

## 최근 공지와 의존성

공식 npm 레지스트리 감사는 현재 고정된 의존성에서 알려진 공지 0건을 반환했다. `dependency-audit.json`은 실제 lockfile SHA-256·조회 시간·원본 응답을 기록한다. `npm run check:dependencies`는 실패·네트워크 오류·잘못된 응답도 실패 증거로 기록한다. 배포는 24시간 이내의 성공 증거와 동일한 lockfile만 허용한다. 오프라인 코드 검증은 가능하며 보안 조회는 별도로 실행한다. npm 감사는 번들에 포함된 C/Wasm 코드의 전체 CVE 검사가 아니다.

공식 레지스트리의 최신 `@ffmpeg/core`는 0.12.10이며 포함 엔진은 실제 `-version` 실행에서 **FFmpeg 5.1.4 / Emscripten 3.1.40**으로 확인했다. 공식 빌드 Dockerfile과 일치한다. FFmpeg 공식 보안 페이지는 그 뒤 5.1.5·5.1.6·5.1.7의 보안 수정을 열거하며, 5.1 브랜치 RELEASE 파일은 5.1.10을 가리킨다. 현재 npm 코어를 최신 FFmpeg로 패치한 것으로 주장하지 않는다. 코어를 교체하려면 Wasm·Emscripten·연결 라이브러리를 함께 재빌드하고 코덱·출력 호환성을 다시 검증해야 한다.

실제 컴파일된 디코더 목록을 한 번 읽고 위 계열을 뺀 허용 목록을 만든다. 목록 파싱·출력량이 비정상이면 처리를 시작하지 않는다. FFprobe와 FFmpeg의 각 입력 앞에 동일 정책을 적용하여 사전 검사 단계의 디코딩도 제한한다. 일반 PNG/JPEG/WebP·H.264/AAC 등 다른 디코더는 유지한다. 제외한 코덱의 로컬 확대·변환·스트림 처리는 실패할 수 있다. 직접 파일 저장은 바이트를 보존하며 별도 로컬 백신 검사 정책을 따른다.

실제 무해한 PNM·JPEG2000·MagicYUV·OpenEXR 표본에서 거부를 확인하고 PNG와 WAV 처리를 유지했다. SANM은 이름 정책 검사이며 실제 SANM 표본 재현은 하지 않았다.

이 조치는 식별한 경로의 노출을 줄이는 완화다. 모든 C/Wasm 취약점·구형 연결 라이브러리를 패치하거나 악성 파일의 무해함을 증명하지 않는다. Worker 격리·프로토콜 제한·자원 한도도 엔진 패치의 대체물이 아니다.

## 재현·수정한 앱 문제

- 네이티브 다운로드가 시작된 뒤 DB 기록 저장·Chrome 조회·완료 처리에서 예외가 발생하면 다운로드 ID를 잃고 자동 검사 추적이 끊길 수 있었다. 시작한 ID를 전체 처리 범위에서 보존하고 중단을 시도한다. 중단을 확인하지 못하면 명시적 검토 상태와 저장 실패 알림을 남긴다. 지속 저장 실패에서도 정리와 알림을 시도하며 정상 검사 완료로 표시하지 않는다.
- FFprobe가 불필요한 전체 태그를 JSON으로 만들고, 크기를 검사하기 전에 JS 문자열로 복사했다. 실제 필요한 필드만 요청하고 MEMFS.stat으로 256,000바이트 한도를 먼저 검사하며 읽은 결과 파일을 정리한다. 검사 전 엔진 오류의 잔여 파일 수명은 Worker 종료로 제한한다. 1MB WAV 메타데이터의 실제 Wasm 검사는 필수 길이 정보를 유지하면서 작은 보고서를 생성한다.
- 백신 호스트는 비문자열 scanner 설정과 깊은 JSON 중첩에서 예외로 종료될 수 있었다. 타입과 파싱 오류를 제한하고 정상 오류 프레임을 반환한다. 임의 셸 실행·링크/파일 식별 검증 완화는 추가하지 않았다.
- manifest의 버전 표시가 이전 버전으로 남아 있던 문제를 1.11.0으로 맞췄다.

URL/리디렉션·발신자와 시크릿 분리·플레이리스트·입력 예산·OPFS 수명·백신 판정·삭제/재검사·명령 배열·네이티브 경로/프로세스·Windows 선택 로직도 검토했다. 확인하지 못한 취약점을 발견했다고 표시하지 않는다. Windows 실제 API, 사용자의 브라우저·설치된 백신 제품·공식 서명 최신성은 별도 검증 범위다.

## 모던 팝업과 공개 인터페이스

아이콘 팝업은 640×600 네이비·민트 테마, 현재 탭 표시, 미디어 카드, 명확한 다운로드 버튼, 라벨이 있는 하단 도구 모음으로 바꿨다. 설정 버튼은 기존 전체 앱을 연다. 외부 글꼴·원격 리소스·새 권한은 추가하지 않는다. 비신뢰 제목은 텍스트로 표시한다. 키보드 초점·모션 감소·고대비 스타일과 빈 화면/미디어/도움말의 잘림을 검사했다. 화면은 `test-results/popup-modern-*.png`에서 볼 수 있다.

배포 앱의 ESM 공개 함수 4개를 제거해 8개 진입점의 공개 export를 **0개**로 줄였다. 필요한 이벤트 리스너는 유지하고 FFmpeg 로더·코어의 default만 남긴다. 하네스도 실제 배포 메시지 리스너를 호출하여 발신자 검증을 통과해야 한다. 별도의 공개 테스트 API로 제품 검증을 우회하지 않는다. 외부 웹페이지용 `web_accessible_resources`나 `externally_connectable`도 추가하지 않는다.

기존 JS/CSS 압축·해시 파일명·소스맵 제외·gzip/AES-256-GCM 엔진 포장을 유지한다. CSP를 완화하거나 eval·동적 코드 생성·디버거 방해·백신 회피를 추가하지 않는다. **브라우저가 실행하는 JS는 읽을 수 있고 자동 복호화 키는 설치본에서 복구 가능하다.** 소스·파일명 대응표·Git 이력도 공개 저장소에 남는다. 이번 조치가 완전한 역공학 차단이나 비밀 보관을 보장하지 않는다.

최종 통합 검사는 단위194개·네이티브50개·브라우저77개·실제 HTTP/3 4개·실제 ClamAV6개·알고리즘5개 영역이 통과했다. 구조 감사는 런타임31개·진입점8개·전체 소스97개를 확인했다.
