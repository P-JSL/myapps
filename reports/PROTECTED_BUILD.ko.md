# 1.13.0 배포 파일 압축·암호화 및 공개 표면 최소화

`npm run build`는 TypeScript 원본을 유지하면서 설치본의 JavaScript/CSS를 압축하고 런타임 리소스를 `assets/<32자리 해시>.<확장자>`로 배치한다. HTML, 아이콘, Worker, 서비스 워커, FFmpeg 로더와 암호화 엔진까지 매 빌드마다 새 이름을 만든다. 원래 디렉터리명·파일명과 소스맵은 설치본에 포함하지 않는다. HTML/ESM/Worker/Chrome URL과 허용된 내부 화면 경로도 함께 바꾼다. `manifest.json`, 사용 설명서, 오픈소스 라이선스 고지는 읽을 수 있게 남긴다.

FFmpeg Wasm은 gzip(level 9)으로 먼저 압축한 뒤 매 빌드의 무작위 키·nonce로 AES-256-GCM 암호화한다. 실행 시 일반 ESM 로더가 내장 Web Crypto로 인증·복호화하고 DecompressionStream으로 압축을 해제한 후 Wasm 엔진에 전달한다. 암호문과 해제 결과의 길이를 각각 제한하며 인증·크기 검사 실패 시 엔진을 실행하지 않는다. `eval`, 동적 코드 생성, 추가 권한, CSP 완화, 백신 우회는 사용하지 않는다. 엔진의 필수 default export와 애플리케이션의 동작은 유지한다.

이 방식은 파일 목록과 바이트의 단순 확인을 어렵게 하는 배포 포장이다. **자동 실행을 위한 복호화 키가 로더에 포함되므로 추출·역공학을 막거나 원본의 기밀성을 보장하지 않는다.** JS/HTML/CSS는 브라우저가 직접 읽는 압축된 평문이다. manifest의 역할·권한 정보도 공개된다. 기존 Git 이력과 전체 소스 ZIP은 그대로 제공되므로 원본을 비공개로 바꾸지 않는다. 파일명 대응표와 암호화 메타데이터는 설치본 밖의 `reports/build.json`에 있으며 공개 저장소에서 열람할 수 있다. 키는 보고서에 별도로 기록하지 않지만 로더에서 복구 가능하다. Chrome Web Store의 난독화 관련 심사를 통과했다는 의미가 아니며 현재 배포는 개발자 모드 로컬 설치용이다.

32,232,419바이트 Wasm은 압축·인증 태그를 포함한 10,257,790바이트 암호문이 된다. 실행 시 복호화·압축 해제에 추가 시간과 임시 메모리가 필요하다. 새 빌드는 매번 다른 salt·키·nonce를 사용하므로 같은 소스에서도 산출물 해시가 달라진다. 따라서 최종 빌드 뒤 브라우저·HTTP/3 검증을 다시 수행하고 해당 해시와 일치하는 ZIP만 배포한다.

업데이트 뒤 확장을 다시 로드하고 기존 설정·미디어 도구 탭은 닫은 후 팝업에서 다시 연다. 매 빌드마다 화면 URL이 바뀌므로 이전 내부 화면 주소를 북마크로 사용하지 않는다.

1.13.0은 디스크 기반 스트림 Worker를 포함한 앱 진입점 9개에도 같은 공개 export 제거·경로 변환을 적용한다. 보호된 실제 Worker의 2GiB 초과 입력 처리와 HTTP/3 실행을 검증하며, 대용량 기능이 추가되어도 권한·CSP·엔진 포장 방식은 확장하지 않는다.

## 별도 비밀번호로 전체 소스 보관

설치본에 키를 넣는 방식과 달리, 외부 비밀번호로 소스 ZIP을 암호화하는 도구도 제공한다. 이 파일은 확장 프로그램에 직접 설치할 수 없으며 개인 보관용이다. 공개 저장소/소스 ZIP의 다른 복사본까지 비공개로 만들지는 않는다. 비밀번호는 사용자가 별도로 보관한다. 자동 배포는 기존 설치·소스 ZIP을 유지하며 임의의 비밀번호를 만들거나 저장소에 비밀번호를 올리지 않는다.

환경변수 `SOURCE_ARCHIVE_PASSWORD`를 로컬에서 안전하게 설정한 뒤 다음 명령을 실행한다. 비밀번호 값 자체는 명령 인수로 전달하지 않는다.

```sh
npm run encrypt:source -- --input artifacts/my-video-app-source.zip --output private-source.zip.enc --password-env SOURCE_ARCHIVE_PASSWORD
npm run decrypt:source -- --input private-source.zip.enc --output restored-source.zip --password-env SOURCE_ARCHIVE_PASSWORD
```

환경변수 대신 `--password-stdin`으로 표준 입력 파이프를 사용할 수 있다. 대화형 터미널 입력은 지원하지 않는다. 출력은 새 파일에만 쓰며 기존 파일·심볼릭 링크를 덮어쓰지 않는다. AES-256-GCM과 scrypt(N=131072,r=8,p=1), 무작위 salt·nonce, 인증된 버전 헤더를 사용한다. 잘못된 비밀번호·손상된 헤더/암호문은 거부한다. 최대 ZIP 32MiB, 비밀번호 4096 UTF-8바이트, KDF 메모리 약 128MiB가 필요하다. 강력한 고유 비밀번호를 사용하고 분실에 대비해 별도로 보관해야 한다.

## 검증

경로의 상대 위치·쿼리/fragment·템플릿 문자열, 문맥이 다른 같은 CSS 파일명, CSP와 권한 보존을 검사한다. 암호화 검사는 실제 Web Crypto 복호화, 압축 해제, 잘못된 키/nonce/인증 문맥/태그, 스트림 길이 오류를 포함한다. 소스 보관 도구는 왕복 복구·비밀번호 오류·변조·크기 한도·기존 파일/링크/FIFO 거부를 검사한다. 브라우저 회귀 검사는 보호된 실제 설치 리소스를 요청하고 다운로드·변환·병합·확대 결과를 검사한다. 실제 확장 설치가 관리자 정책으로 차단된 환경이라는 기존 한계는 유지한다.

## 1.11.0 공개 표면 축소

앱 진입점 8개의 ESM 공개 export 4개를 배포 시 제거하여 공개 함수를 0개로 만든다. 이벤트 리스너는 유지하고 엔진 모듈의 필수 default만 남긴다. AST·실제 namespace 검사와 실제 제품 메시지 리스너를 통한 브라우저/HTTP3 회귀 검사로 동작을 확인한다. 외부 연결 허용 설정이나 권한·CSP 완화는 추가하지 않는다. 이는 함수 이름·호출 인터페이스의 노출 축소이며, 위의 복호화 키·평문 JS·공개 소스 이력이라는 한계는 유지된다.

## 1.12.0 시험 자료 배포 방지

내장 정적 검사의 무해한 표준 백신 시험 표식은 테스트 실행 중 메모리에서 구성한다. 빌드·패키지 작성 시 배포 리소스와 소스·네이티브 도우미·보고서에 표식 원문이 남지 않았는지 검사한다. 시험 파일·서명 DB는 ZIP에 넣지 않는다. 내장 검사의 규칙·한계는 `INTERNAL_SCAN.ko.md`에 있으며 기존 압축·인증·공개 표면 정책은 유지한다.
