# My Video App 1.9.0 로컬 버전 검증

환경: Node.js 24.19.0, Chromium 154.0.8037.57, Linux x86_64.
브라우저 하네스의 IndexedDB·미디어 처리·Worker·Wasm·OPFS·파일 출력은 실제 실행한다.
Chrome 확장 API는 테스트 대역이며 실제 설치 전체가 통과했다는 의미가 아니다.
현재 TypeScript 단위 테스트 121개와 브라우저 하네스 시나리오 77개가 모두 통과했다.
팝업·수집기 세부 검사 6개와 DB 세부 검사 19개는 각각 브라우저 시나리오 한 개씩의 내부 검사이며 합계에 다시 더하지 않는다.
최종 실행 결과와 빌드 해시는 `reports/browser.json`과 실제 검사 로그를 기준으로 확인한다.

실행 가능한 검사: `npm run verify`. 실제 수행 결과의 시나리오와 빌드 해시는
`reports/browser.json`, 설치 구성은 `reports/build.json`에 있다. 기존 원본 전용
구현을 제거하면서 해당 구현에만 의존하던 과거 비교 테스트도 제거했고, 현재
로컬 엔진과 공통 구성요소의 검사를 유지/추가했다. 실패한 검사를 생략한 것은 아니다.

1.2.0 추가 검사에서 포함 FFmpeg 코어의 VP9 인코더가 메모리 접근 오류를 재현했다.
따라서 WebM 출력은 실제로 성공한 VP8/Opus로 제공하며 실패한 VP9 인코딩을 통과로
표기하지 않는다. AAC/Matroska 병합의 초기 코덱 지연을 제외하고 안정된 음성 구간의
주파수를 측정한다. 영상은 코덱 복사 스트림의 해시를 비교한다.

별도 `npm run test:http3`의 4개 검사는 임시 TLS/QUIC 서버와 폐기할 Chrome 프로필로
실제 HTTP/3 MP4·Range·HLS/Wasm 저장 및 인증서 검증을 수행한다. 결과는 `reports/http3.json`.
시험 브라우저만 루프백 QUIC 경로를 지정하며 제품은 Chrome 자동 협상을 사용한다.
제품의 실제 확장 설치/API 통합과 공개 사이트의 자동 협상 전체를 검증한 것은 아니다.

실서비스 사이트별 로그인·서명·지역·CDN 호환성, 모든 HLS/DASH 변형, 라이브/DRM,
원본의 모든 전용 기능은 동등성 보장 범위가 아니다. 지원 범위는 `LOCAL_MODE.ko.md` 참조.
검증용 입력/출력·화면은 `test-results`에 있으며 설치/소스 ZIP에 포함하지 않는다.


## 로컬 백신 검사 검증

- TypeScript 단위 검사 121개에는 백신·확인 상태와 수명주기 회귀 검사가 포함됩니다: 요청 ID·해시·크기 검증, 연결/권한 실패, 감염·미검사 확인 대기, 명시적 동의·오래된 토큰 거부, 실제 임시 파일 삭제와 삭제 실패, Chrome 경고 우선 처리, 다운로드 기록 소실 복구, 업스케일링 복사본 해시 비교를 검사합니다.
- Python 네이티브 호스트 단위 검사 48개: 제한된 프레임·허용된 요청, 일반 파일·링크 거부, 파일 변경·출력량·시간 제한, 오류 판정과 사용자별 설치를 검사합니다. 테스트용 백신 대역은 실제 무해한 subprocess로 실행합니다.
- 브라우저 하네스 77개에는 위험 확인창·문자열 렌더링·삭제 실패 후 복구·미검사 파일 명시적 유지·Chrome 검토·선택 권한 동작이 포함됩니다. 확장 API와 백신 포트는 대역이며 실제 Chrome 차단 탐지나 네이티브 설치 통합을 뜻하지 않습니다. 비동기 저장소/OPFS 조건은 Node에서 반복하여 기다립니다.
- 별도 실제 **ClamAV 1.4.6 + native messaging 프레임 검사 6개**는 정상 MP4, 무해한 커스텀 서명, 임시 표준 EICAR 시험 문자열, 암호화된 ZIP의 MP4 위장에 대한 미검사 판정, 잘못된 DB 오류를 확인했습니다. `reports/antivirus.json`은 호스트 소스 해시를 기록합니다. 사용자 전용으로 추출한 엔진과 **시험 전용 로컬 서명 DB**를 사용했으며 공식 서명 최신성·범위는 검증하지 않았습니다. 시험 문자열과 DB는 패키지에 포함하지 않았습니다.
- Windows Defender 실제 실행 및 사용자 PC의 실제 확장 설치/native messaging 연결은 이 Linux 클라우드에서 검증하지 않았습니다. 상세 설치 및 검사 시점의 한계는 `SECURITY_DOWNLOADS.ko.md`에 있습니다.


## 1.5.0 Windows 백신 자동 선택 검증

Windows 기본값은 Defender이며 활성 타사 백신은 Windows Security Center COM 정보와 AMSI 공급자 등록이 일치할 때 표준 인터페이스로 연결합니다. ClamAV의 단순 설치는 Windows 기본값을 바꾸지 않습니다. 명시적 `--scanner` 또는 `--clamav` 선택만 우선합니다. Defender는 기존 OS 보호 정책을 존중하고 활성 Normal 모드인지 확인합니다.

Windows 관련 네이티브 검사는 Windows 기본 선택·활성/비활성 타사 제품·미지원 공급자·불명확한 조회·결과·HRESULT·정리·파일 전체 버퍼·128MiB 제한을 포함합니다. Windows COM/AMSI/Defender 부분은 대역입니다. `reports/native-tests.json`은 호스트·Windows 모듈·설치 도구 해시를 기록하며 패키징 시 일치를 요구합니다. 실제 Windows 백신 제품별 연동은 이 Linux 환경에서 검증하지 않았습니다.


## 1.6.0 교차 검토 회귀 검사

- 리디렉션 HLS 마스터·각 자식 목록, DASH 리디렉션, DASH 부모 템플릿 상속·자식 타임라인 대체를 실제로 저장하고 전체 디코드합니다.
- 상태 요청이 실제 도우미에 접속하는지, 미설치가 연결 성공으로 표시되지 않는지, 준비된 경우만 대기 파일을 재검사하는지 확인합니다. 실제 ClamAV 연결 확인도 별도 native 프레임으로 검사합니다.
- 주기 갱신 시 키보드 초점, 설정 재열기·지연 복원·시크릿 분리를 실제 브라우저에서 검사합니다.
- 철회 중 복사·대기 제안이 등록되지 않는지, 새 정상 검사 뒤 새 세대의 제안만 복구되는지 검사합니다.
- 1.6.0 당시 TypeScript 72개, 네이티브 44개, 브라우저 64개, 실제 ClamAV 5개, 실제 HTTP/3 4개를 검증했습니다. Windows API 및 확장 API 대역이라는 기존 한계는 유지합니다.


## 1.7.0 전체 점검 회귀 검사

- 실제 패키지 작성기를 격리된 임시 디렉터리에서 실행하여 파일·디렉터리 심볼릭 링크 거부, 외부 시험 내용 미포함, 실패 시 새 해시 목록 미발행과 정상 다섯 ZIP·해시를 검사합니다.

담당별 재현·수정·독립 승인과 남은 검증 한계는 `FULL_AUDIT.ko.md`를 참고하세요.

## 1.9.0 내장 DB 자동 관리 검증

- TypeScript **121개**, Python 네이티브 **48개**, Chromium 하네스 **77개**가 통과했습니다. DB **19개 세부 검사**는 브라우저 한 시나리오에 포함하며 합계에 더하지 않습니다. 세부 결과·소스 해시·페이지 오류는 database.json에 있습니다.
- 실제 Chromium IndexedDB에서 자동 스키마·색인 생성, 순서 보존, 재연결, 반복·동시 이전, 커밋 후 이전 원본 정리를 확인했습니다. 오래된 이전 원본이 새 기록을 덮어쓰지 않습니다.
- 실제 트랜잭션 중단, 명시적으로 주입한 할당량·열기 오류, 차단 업그레이드와 뒤늦은 취소, versionchange·알 수 없는 새 버전, 이전 원본 조회·삭제 실패를 확인했습니다. 실제 디스크 고갈 시험은 아닙니다.
- 정상 상태의 기록 200개 우선 보존, 복사 큐 4개·512MiB·24시간과 다음 접근 시 관리, 시크릿 IDB·이전 저장소 호출 0을 검사했습니다. 손상·중복 이전 데이터는 복구용으로 보존하고 시크릿 항목은 DB와 복구 저장소에 복사하지 않습니다.
- 현재 DB 기록 손상, 재연결 전후 이전 표시 누락, 열린 연결의 표시 누락과 60초 뒤 자동 관리도 원본을 변경하지 않고 실패합니다. 빈 목록 대체·DB 초기화로 오류를 숨기지 않습니다.
- Node 회귀 검사는 DB 준비·조회·상태·커밋 실패 시 파일 보존, 복구 대기 시 자동 삭제·색인 변경 보류, 시작 시 고아 파일 보존과 시크릿 DB 무접근을 확인했습니다. 이 워크플로의 DB 어댑터는 대역이며 DB 자체는 실제 브라우저에서 검사했습니다.
- 지연 설정 검사는 실제 읽기·커밋을 유지하고 완료 콜백 전달만 보류하는 명시적 테스트 장치를 사용합니다. 즉시 다운로드 대기·늦은 복원·사용자 선택 우선 동작이 통과했습니다.
- 독립 검토 에이전트가 소스, DB19/브라우저77 결과·오류0·외부 요청0, 현재 빌드 해시 일치를 확인했습니다. 설치된 확장의 실제 Chrome API 및 Windows 백신 실행이라는 기존 검증 한계는 유지합니다.

## 팝업·실제 미디어 파일 저장

- 640×600 어두운 팝업의 설정·기록·폴더·도움말·로컬 메모·미디어 도구·강제 감지 동작을 실제 DOM에서 검사했다. 설정은 기존 전체 앱을 연다. 새 영상 다운로드 아이콘을 사용한다.
- 실제 IndexedDB 설정 완료 전 다운로드를 기다리고, 시크릿 팝업은 일반 DB 접근 0회이며, 외부 제목은 텍스트로 렌더링한다. 수집기는 같은 확장 발신자·유효 nonce만 받고 모든 캡처 응답을 기다린다. 결과는 `reports/popup.json`.
- text/plain·잘못된 .txt 첨부명을 가진 MP4/WebM을 실제 브라우저로 저장했다. MIME·정규 확장자·원본 SHA256·영상/음성 트랙·전체 FFmpeg 디코딩을 확인했다. 업스케일링 끄기 상태의 background 경로도 검사했다.
- HTML·일반 텍스트·video/mp4로 위장한 HTML은 브라우저 다운로드 API 전에 거부했다. 큰 ID3 태그 MP3, 별도 Range 확인의 한도·취소·시간 초과도 검사한다.
- 별도 검토 에이전트가 MP3 호환성 오류를 재현해 수정했고, DB 복구 보존·재감지 티켓·저장 경로를 교차 검토했다. 최종 브라우저 통과와 동일 빌드 패키징을 승인 조건으로 삼았다.
- 형식 헤더 검사는 파일 전체 재생·무해함 보증이 아니다. 직접 다운로드 fallback의 별도 확인 요청은 후속 다운로드와 동일성을 보증하지 않으며, 64KiB보다 큰 ID3 태그 MP3를 거부할 수 있다.

GitHub에 추가된 `.txt` 예제(SHA256 `704a5e15ae1068e4df52a8bcff04270efdad595cf685e0eccff86ab335471a46`)도 검사했다. 실제 형식은 M4A/AAC, 길이는 약 0.488초이며 영상 트랙이 없다. 새 분류기는 audio/mp4와 .m4a를 반환한다. 이 오디오 조각만으로 전체 영상을 복원한 것으로 주장하지 않는다.
