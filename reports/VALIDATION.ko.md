# My Video App 1.7.0 로컬 버전 검증

환경: Node.js 24.19.0, Chromium 154.0.8037.57, Linux x86_64.
브라우저 하네스의 미디어 처리·Worker·Wasm·OPFS·파일 출력은 실제 실행한다.
Chrome 확장 API는 테스트 대역이며 실제 설치 전체가 통과했다는 의미가 아니다.
현재 단위 테스트 88개와 브라우저 하네스 시나리오 71개가 모두 통과했다.
최종 실행 결과와 빌드 해시는 `reports/browser.json`과 실제 검사 로그를 기준으로 확인한다.

실행 가능한 검사: `npm run verify`. 실제 수행 결과의 시나리오와 빌드 해시는
`reports/browser.json`, 설치 구성은 `reports/build.json`에 있다. 기존 원본 전용
구현을 제거하면서 해당 구현에만 의존하던 과거 비교 테스트도 제거했고, 현재
로컬 엔진과 공통 구성요소의 검사를 유지/추가했다. 실패한 검사를 생략한 것은 아니다.

1.2.0 추가 검사에서 포함 FFmpeg 코어의 VP9 인코더가 메모리 접근 오류를 재현했다.
따라서 WebM 출력은 실제로 성공한 VP8/Opus로 제공하며 실패한 VP9 인코딩을 통과로
표기하지 않는다. AAC/Matroska 병합의 초기 코덱 지연을 제외하고 안정된 음성 구간의
주파수를 측정한다. 영상은 코덱 복사 스트림의 해시를 비교한다.

별도 `npm run test:http3`의 4개 검사는 임시 TLS/QUIC 서버와 폐기할 Chrome 프로필로
실제 HTTP/3 MP4·Range·HLS/Wasm 저장 및 인증서 검증을 수행한다. 결과는 `reports/http3.json`.
시험 브라우저만 루프백 QUIC 경로를 지정하며 제품은 Chrome 자동 협상을 사용한다.
제품의 실제 확장 설치/API 통합과 공개 사이트의 자동 협상 전체를 검증한 것은 아니다.

실서비스 사이트별 로그인·서명·지역·CDN 호환성, 모든 HLS/DASH 변형, 라이브/DRM,
원본의 모든 전용 기능은 동등성 보장 범위가 아니다. 지원 범위는 `LOCAL_MODE.ko.md` 참조.
검증용 입력/출력·화면은 `test-results`에 있으며 설치/소스 ZIP에 포함하지 않는다.


## 로컬 백신 검사 검증

- TypeScript 단위 검사 88개에는 백신·확인 상태와 수명주기 회귀 검사가 포함됩니다: 요청 ID·해시·크기 검증, 연결/권한 실패, 감염·미검사 확인 대기, 명시적 동의·오래된 토큰 거부, 실제 임시 파일 삭제와 삭제 실패, Chrome 경고 우선 처리, 다운로드 기록 소실 복구, 업스케일링 복사본 해시 비교를 검사합니다.
- Python 네이티브 호스트 단위 검사 48개: 제한된 프레임·허용된 요청, 일반 파일·링크 거부, 파일 변경·출력량·시간 제한, 오류 판정과 사용자별 설치를 검사합니다. 테스트용 백신 대역은 실제 무해한 subprocess로 실행합니다.
- 브라우저 하네스 71개에는 위험 확인창·문자열 렌더링·삭제 실패 후 복구·미검사 파일 명시적 유지·Chrome 검토·선택 권한 동작이 포함됩니다. 확장 API와 백신 포트는 대역이며 실제 Chrome 차단 탐지나 네이티브 설치 통합을 뜻하지 않습니다. 비동기 저장소/OPFS 조건은 Node에서 반복하여 기다립니다.
- 별도 실제 **ClamAV 1.4.6 + native messaging 프레임 검사 6개**는 정상 MP4, 무해한 커스텀 서명, 임시 표준 EICAR 시험 문자열, 암호화된 ZIP의 MP4 위장에 대한 미검사 판정, 잘못된 DB 오류를 확인했습니다. `reports/antivirus.json`은 호스트 소스 해시를 기록합니다. 사용자 전용으로 추출한 엔진과 **시험 전용 로컬 서명 DB**를 사용했으며 공식 서명 최신성·범위는 검증하지 않았습니다. 시험 문자열과 DB는 패키지에 포함하지 않았습니다.
- Windows Defender 실제 실행 및 사용자 PC의 실제 확장 설치/native messaging 연결은 이 Linux 클라우드에서 검증하지 않았습니다. 상세 설치 및 검사 시점의 한계는 `SECURITY_DOWNLOADS.ko.md`에 있습니다.


## 1.5.0 Windows 백신 자동 선택 검증

Windows 기본값은 Defender이며 활성 타사 백신은 Windows Security Center COM 정보와 AMSI 공급자 등록이 일치할 때 표준 인터페이스로 연결합니다. ClamAV의 단순 설치는 Windows 기본값을 바꾸지 않습니다. 명시적 `--scanner` 또는 `--clamav` 선택만 우선합니다. Defender는 기존 OS 보호 정책을 존중하고 활성 Normal 모드인지 확인합니다.

Windows 관련 네이티브 검사는 Windows 기본 선택·활성/비활성 타사 제품·미지원 공급자·불명확한 조회·결과·HRESULT·정리·파일 전체 버퍼·128MiB 제한을 포함합니다. Windows COM/AMSI/Defender 부분은 대역입니다. `reports/native-tests.json`은 호스트·Windows 모듈·설치 도구 해시를 기록하며 패키징 시 일치를 요구합니다. 실제 Windows 백신 제품별 연동은 이 Linux 환경에서 검증하지 않았습니다.


## 1.6.0 교차 검토 회귀 검사

- 리디렉션 HLS 마스터·각 자식 목록, DASH 리디렉션, DASH 부모 템플릿 상속·자식 타임라인 대체를 실제로 저장하고 전체 디코드합니다.
- 상태 요청이 실제 도우미에 접속하는지, 미설치가 연결 성공으로 표시되지 않는지, 준비된 경우만 대기 파일을 재검사하는지 확인합니다. 실제 ClamAV 연결 확인도 별도 native 프레임으로 검사합니다.
- 주기 갱신 시 키보드 초점, 설정 재열기·지연 복원·시크릿 분리를 실제 브라우저에서 검사합니다.
- 철회 중 복사·대기 제안이 등록되지 않는지, 새 정상 검사 뒤 새 세대의 제안만 복구되는지 검사합니다.
- 1.6.0 당시 TypeScript 72개, 네이티브 44개, 브라우저 64개, 실제 ClamAV 5개, 실제 HTTP/3 4개를 검증했습니다. Windows API 및 확장 API 대역이라는 기존 한계는 유지합니다.


## 1.7.0 전체 점검 회귀 검사

- 현재 결과: TypeScript **88개**, Python 네이티브 **48개**, Chromium 하네스 **71개**, 실제 ClamAV **6개**, 실제 HTTP/3 **4개**입니다. 실패·생략 없이 통과한 최종 실행과 해시를 JSON 보고서로 확인합니다.
- 시크릿 기록·공유 저장소·확대 큐의 격리, 기록 삭제 후 늦은 경고 및 재시작 시 복사본 철회, 업데이트 후 중단 준비 복구, 일반 서비스 워커 활성화 시 진행 작업 보존을 검사합니다.
- 비동기 탭 조회 후 탐색·종료된 탭에 미디어가 다시 등록되지 않는지 확인합니다. 기록 상한에서도 미해결 검토·다운로드를 우선 유지합니다.
- 실제 100초 타임스탬프가 있는 DASH 조각에 상속된 presentationTimeOffset과 마지막 r=-1을 적용하여 병합·전체 디코드합니다. SegmentList의 상속된 초기화와 하위 목록 대체도 실제 병합·디코드합니다. 별도로 Chromium에서 계획 불변 조건 10개를 확인합니다.
- 저장 옵션 복원이 지연된 동안 미디어 행·직접 주소 다운로드가 대기하고, 복원 값 또는 사용자가 새로 고른 값으로 시작하는지 확인합니다. 이 부분의 확장 API는 대역입니다.
- 시크릿 미디어 도구가 일반 큐·알림 설정을 읽거나 변경하지 않고, 직접 선택한 이미지는 실제 Worker에서 확대·저장하는지 확인합니다.
- 실제 패키지 작성기를 격리된 임시 디렉터리에서 실행하여 파일·디렉터리 심볼릭 링크 거부, 외부 시험 내용 미포함, 실패 시 새 해시 목록 미발행과 정상 다섯 ZIP·해시를 검사합니다.
- ClamAV의 암호화 파일 및 대소문자가 섞인 경고·오류를 검사 미완료로 분류합니다. 암호화와 실제 탐지가 함께 있으면 탐지 결과를 유지합니다. 실제 암호화 시험에는 시험용 `zip` 명령을 사용하며, DB·시험 문자열·암호화 파일은 임시 디렉터리에서 제거합니다.
