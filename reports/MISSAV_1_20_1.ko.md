# Chrome 확장 다운로드 실패 수정 · 1.20.1

사용자가 1.20.0 MissAV 포함 확장에서 `미디어 요청 실패 (403)`을 보고했다. 2026-11-17 한국 시간 기준으로 요청 경로를 다시 점검했다.

## 재현과 원인

관리 Chromium의 설치 제한을 변경하지 않고, 프로젝트에 고정된 Playwright의 Chrome for Testing을 별도로 설치해 실제 확장을 로드했다. 기존 검사는 Chrome 메시지 API에 테스트 대역을 사용했으므로 이 경로 누락을 발견하지 못했다.

1.20.0에서는 감지 목록의 항목은 실제 탭 ID를 가졌지만 **직접 주소 입력과 실패 기록의 재시도는 `tabId: -1`로 새 항목을 만들었다.** 이 두 진입점은 재생 탭 연결을 사용하지 않고 확장 문서에서 미디어를 요청했다. 실제 확장으로 자체 영상을 재현했을 때 감지 다운로드는 성공하고 주소 입력·재시도는 실패했다. 테스트 응답을 통한 실제 HTTP 403 실패도 별도 회귀 검사에 포함했다.

같은 재생목록 경로에서 서명 쿼리만 갱신된 경우 오래된 주소와 최신 주소가 함께 남는 문제도 확인했다.

## 수정

- 직접 주소와 재시도는 같은 영상 UUID의 감지 항목에서 원래 재생 탭을 복원한다. 동일 경로의 최신 관측 주소를 쿼리·대소문자·경로 그대로 사용한다.
- 서비스 워커가 종료되어 감지 목록이 사라진 경우, 열려 있는 MissAV 페이지의 실제 콘텐츠 스크립트에 같은 영상인지 조회한다. 다른 UUID·호스트·인증 정보가 들어간 주소·다른 브라우징 모드의 응답은 받지 않는다.
- 원래 재생 탭을 찾을 수 없으면 새로고침·재생 안내를 표시하고 미디어 요청을 시작하지 않는다. 확장 문서의 요청으로 조용히 되돌아가지 않는다.
- 같은 경로에 새 서명 주소가 관측되면 오래된 관측 주소를 제거한다. 영상 조각 URL이나 서명 값을 직접 조합하지 않는다.
- 새 Chrome 권한과 쿠키 추출을 추가하지 않는다. 일반판 확장은 기존 배포 파일 그대로 유지한다. Windows 엔진은 바꾸지 않고 1.20.1 버전 표시를 갱신한다.

## 검증과 배포

집중 TypeScript 검사 30개, 타입 검사, 소스 정책, 기존 브라우저 처리 검사 4개를 실행한다. 새 실제 확장 설치 검사 6개는 Chrome API를 대체하지 않고 다음을 확인한다.

1. 감지 항목에서 원래 재생 페이지를 통해 MP4 저장.
2. 직접 m3u8 입력에서 원래 탭을 복원하여 MP4 저장.
3. 실제 403 실패 항목을 재시도해 원래 탭에서 MP4 저장.
4. 실제 콘텐츠 스크립트 메시지 채널에서 같은 영상의 원본 주소 조회.
5. 원래 탭을 닫으면 네트워크 요청 전 안내 표시.
6. 만료 서명 주소 입력 시 현재 관측 주소로 갱신하여 MP4 저장.

출력 파일은 실제 Chrome 다운로드 API로 저장하고 FFprobe로 영상·음성을 확인한다. 모든 디코딩 영상 프레임의 SHA-256을 자체 원본 영상과 비교한다. 실제 Chrome의 콘텐츠 스크립트·서비스 워커·offscreen 문서·Worker·OPFS·FFmpeg를 사용한다. 네트워크 응답만 자체 영상 fixture로 제공한다.

Windows 패키지는 기존 집중 통합 검사 11개와 네이티브 화면 검사 1개를 포함된 Python·Qt로 실행한다. 모든 검사와 ZIP 파일별 해시·소스 일치를 통과한 뒤 `v1.20.1-preview.1`로 공개한다. `INSTALLED-EXTENSION-VALIDATION.json`에 실제 확장 설치 여부·브라우저 버전·6개 결과를 기록한다.

실제 사이트 영상 전체 다운로드와 사용자 PC 환경은 아직 미검증이다. 새 확장을 로드한 뒤 **원래 MissAV 탭을 새로고침하고 영상을 재생한 후** 다운로드해야 한다. 이전 버전의 콘텐츠 스크립트 연결은 확장 업데이트로 끊길 수 있다. 환경 자체는 게시하지 않는다.
