# 에이전트 교차 검토와 적용 내역 · 1.6.0

다운로드·보안/백신·사용성 담당 에이전트 3개가 기존 1.5.0 코드를 각각 검토했습니다. 재현 가능한 결함과 반복 사용에서 필요한 기능을 우선 적용했습니다.

| 발견한 부족한 점 | 적용한 개선 | 확인 방법 |
| --- | --- | --- |
| HLS/DASH 주소가 리디렉션되면 상대 조각 주소를 원래 주소 기준으로 요청 | 실제 응답 URL을 기준으로 해석. HLS 마스터와 자식 목록 각각 적용 | 실제 마스터·영상·음성 리디렉션 및 DASH 리디렉션 후 전체 영상 디코드 |
| DASH 자식 `SegmentTemplate`가 있으면 부모의 나머지 설정을 잃음 | 속성을 개별 상속하고, 자식 타임라인이 부모 타임라인을 대체 | 부모 속성·타임라인 상속 및 자식 대체 두 종류의 실제 영상 저장·디코드 |
| ‘백신 연결’이 도우미에 접속하지 않고 확인 문구를 표시 | 실제 Native Messaging 상태 요청. 도우미·선택 엔진·미지원 사유 표시 | 미설치·잘못된 응답·준비됨 상태와 실제 ClamAV 연결 검사 |
| 2초마다 목록을 다시 만들 때 키보드 초점 소실 | 같은 행·같은 동작으로 초점 복원. 목록 밖과 대화상자 초점은 유지 | 자동 갱신을 기다리는 실제 브라우저 키보드 초점 검사 |
| 화면을 다시 열 때 화질·저장 형식 초기화 | 검증된 설정을 로컬에 저장·복원. 늦은 복원이 새 선택을 덮어쓰지 않음 | 다시 열기·지연 복원·시크릿 창 분리 검사 |
| 복사 도중 철회된 업스케일링 제안이 잠시 다시 등록될 수 있음 | 호출 세대를 묶고 복사·등록 후 재확인 | 복사 도중 철회와 이미 대기 중인 오래된 제안이 등록되지 않는 회귀 검사 |
| Chrome 경고를 해결하고 새 백신 검사까지 통과해도 제안이 영구 차단 | 새 정상 검사 뒤에만 새 제안 세대 허용 | 철회 후 기존 호출은 차단하고 새 승인 뒤의 복사본만 생성하는 검사 |

새 백신 상태 요청은 사용자 파일을 읽거나 검사하지 않습니다. Defender 활성 모드, AMSI 초기화·세션, ClamAV 실행 상태를 확인합니다. ‘연결 준비됨’은 특정 파일의 위협 미탐지 판정이 아니며, ClamAV 서명 DB 상태도 파일의 실제 검사에서 별도로 확인합니다. 초기 화면과 주기 갱신에서 네이티브 도우미를 자동 실행하지 않습니다.

설정은 일반 창에서만 저장하며 시크릿 창은 일반 창의 화질·저장 형식을 읽거나 덮어쓰지 않습니다. Chrome의 보호 설정과 기존 백신 선택 정책은 그대로 사용합니다.

검증 결과는 `VALIDATION.ko.md`, `browser.json`, `native-tests.json`, `antivirus.json`, `http3.json`에 있습니다. 실제 확장 설치는 이 환경의 관리자 정책으로 차단되어 확장 API는 대역이며, Windows 백신 API도 Linux 환경에서는 대역입니다. 이 제한은 실제 Windows 통합 검증이 끝났다는 뜻으로 바꾸지 않았습니다.

사이트별 전용 추출기, DRM/라이브 처리, 모든 타사 백신 연결을 이번 개선으로 추가했다고 주장하지 않습니다. 기존 지원 범위를 유지하면서 확인된 결함을 수정했습니다.
