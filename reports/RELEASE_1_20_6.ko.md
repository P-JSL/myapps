# 1.20.6 · 대용량 영상 저장 시간 개선

MissAV 확장의 미디어 전달은 Chrome 148 이상에서 바이트 배열을 사용하고, 구형 Chrome에서는 Base64로 전송한다. 각 요청은 이전과 같이 최대 128KiB 프레임을 사용하고, 한 번에 최대 네 프레임을 요청한다. 다른 탭에서 수행된 요청의 연결 통계를 기다리는 시간을 없앴다. 전송 중 검사에서는 서명이 시작될 수 있는 바이트만 기존 검사에 넘기며, 출력 파일은 고정 크기 블록으로 읽어 전체 SHA-256을 계산한다.

Linux의 Chromium 156.0.8078.4에서 v1.20.5 공개 ZIP과 수정판을 같은 조건으로 비교했다. Playwright가 동일한 합성 HLS 응답을 제공했고, 설치된 확장의 주소 입력 UI로 다운로드를 시작했다. 각 실행은 새 브라우저 프로필을 사용했다. 주소 폼을 열기 직전부터 Chrome 저장 완료까지 측정했으며 조각 다운로드, 병합, 앱 내부 해시와 저장이 포함됐다. [측정 JSON](LARGE_VIDEO_SPEED_COMPARISON.json)

| 순서 | 빌드 | 저장 시간 |
| --- | --- | ---: |
| 1 | 수정판 | 78.28초 |
| 2 | v1.20.5 | 121.60초 |
| 3 | v1.20.5 | 124.18초 |
| 4 | 수정판 | 82.81초 |

평균 저장 시간이 **122.89초에서 80.54초로 34.5% 줄었다.** 수정판의 가장 느린 실행을 기존판의 가장 빠른 실행과 비교해도 **31.9% 단축**됐다. 각 실행에서 921개 HLS 구간을 모두 받아 2,392,906,379바이트의 MP4를 저장했다. 네 파일의 SHA-256과 재생 시간이 일치했고, 영상·음성과 처음·끝 디코딩을 확인했다. 마지막 기존판과 수정판에서는 앱이 계산한 SHA-256도 독립적으로 계산한 저장 파일의 SHA-256과 일치했다.

위 수치는 합성 영상과 하나의 Chrome 환경에서 측정했다. 실제 사이트를 대상으로 한 Windows 비교는 v1.20.5에서 HTTP 403이 발생해 완료되지 않았다. Windows의 별도 합성 영상 비교는 인증서 준비 단계에서 중단했다. 사이트, 회선, 브라우저와 디스크에 따라 저장 시간은 달라진다. [실사이트 Windows 실행](https://github.com/P-JSL/myapps/actions/runs/45956169700)

일반판과 MissAV판 설치 파일은 각각 `extensions/standard/`와 `extensions/missav/`에 있다. Windows 통합 앱은 일반 미디어·YouTube와 MissAV를 지원한다. [v1.20.6 릴리즈](https://github.com/P-JSL/myapps/releases/tag/v1.20.6)
