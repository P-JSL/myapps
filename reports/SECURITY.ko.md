# 보안 검토

범위는 업로드된 배포본의 신뢰 경계와 추가 코드다. 제품 전체 침투 테스트나
모든 번들/코덱에 대한 취약점 부재 보증은 아니다. 원본 계정·유료 기능·DRM 판정은
변경하지 않았다. 보안을 강화하기 위해 악성/비정상 입력을 원본과 다르게 거부한다.

| 확인한 문제/위험 | 조치 | 검증 |
| --- | --- | --- |
| 서비스 메시지에서 채널만 확인 | sender ID·URL·탭·메시지 구조/크기/깊이 검사 | 단위 테스트 |
| 페이지에서 권한 있는 서비스 요청을 위조할 가능성 | 활성화/YouTube 평가/VK 대리 요청을 원래 사이트와 목적지로 한정 | 단위 테스트 |
| 예측 가능한 BroadcastChannel과 검증 없는 수신 | 6개 isolated 수신기에 스키마 검사 추가 | 단위 및 빌드 패치 검사 |
| QuickJS 평가의 자원 소모 | 2초·128MiB 힙·2MiB 스택 한도 | API 존재/패치 검사; 실제 확장 안의 한도 작동은 미검증 |
| 과도한 미디어와 잘못된 파일 형식 | 매직 바이트·입력 크기·픽셀·길이·실행 시간·출력 크기 제한 | 실제 브라우저 거부/취소/변환 테스트 |
| 플레이리스트를 통한 원격/임의 파일 요청 | 지원 서명만 허용하고 FFmpeg protocol whitelist를 file,pipe로 제한, 가상 FS에 정해진 파일명만 사용 | 단위 및 외부 요청 없음 검사 |
| 동시 큐 작업이 파일을 지우거나 인덱스를 덮어씀 | 서비스/여러 탭에 공통인 navigator.locks 적용 | 실제 2개 탭·OPFS 테스트 |
| 임시 영상이 장기 잔류/시크릿 자료 노출 | UUID 경로, TTL, 4개/512MiB, 삭제/비활성화, 시크릿 복사 제외 | 브라우저 하네스 및 단위 테스트 |
| HTML/파일명/오류 문자열 삽입 | textContent, 출력 파일명 정리, 새 UI 전용 CSP | 단위 및 브라우저 화면 검사 |
| 수정된 원본 번들에 엉뚱한 패치 적용 | 모든 입력 파일 SHA-256, 정확한 패치 횟수, 패치 실패 시 빌드 중단 | 빌드 |

## 잔여 위험

- `<all_urls>`와 기존 권한은 호환성 때문에 유지한다. 기존 확장의 권한 표면을
  최소 권한 제품 수준으로 재설계한 것은 아니다.
- 사이트 MAIN world는 사이트 스크립트와 같은 신뢰 영역이다. 채널 검증은 사이트가
  거짓 미디어 정보를 주는 것을 인증하거나 막는 기능이 아니다.
- 보존한 기존 JS와 2개 원본 Wasm, 원격 동작 규칙/구독/네트워크 파서 전체의
  안전성을 증명하지 않았다. 새 FFmpeg Wasm도 코덱 취약점이 없다고 보증하지 않는다.
- npm audit는 npm 패키지 메타데이터에 대한 검사다. 번들 내부 코드와 네이티브
  Wasm 코덱의 모든 CVE를 검사하지 않는다. 별도 코덱/번들 감사와 업데이트가 필요하다.
- 입력/출력 한도와 -max_alloc은 총 메모리의 엄격한 상한을 보장하지 않는다.
  압축 해제·디코딩으로 큰 메모리를 쓸 수 있어 Worker 종료/브라우저 격리에 의존한다.
- 업스케일링은 새로 인코딩한 결과라 원본 바이트·모든 트랙·모든 메타데이터가 같지 않다.
  따라서 원본 다운로드 파일을 반드시 별도로 보존한다.
- 실제 Chrome 확장 API(알림 버튼, offscreen, 서비스 워커 재시작, 사이드패널) 통합은
  이 클라우드의 설치 금지 정책 때문에 미검증이다. 외부 사이트/인증/구독도 미검증이다.

## 재현 가능한 점검

`npm run verify`는 타입 검사 → 32개 단위 회귀 테스트 → 입력 해시/패치 빌드 →
실제 브라우저 하네스의 미디어·큐 테스트를 실행한다. 패키지 감사는
`npm audit --json`으로 실행하며 결과를 `reports/npm-audit.json`에 보관했다.
취약점이 없다는 단정 대신 검증 범위와 미검증 범위를 함께 유지한다.
