# My Video App 1.9.1 리팩토링 분석

기준은 GitHub의 `5310816`(1.9.0)이다. 소스, manifest·HTML·Worker 진입점, 빌드 산출물, 테스트, 네이티브 코드를 함께 검토했다. 기능 추가보다 중복 제거와 변경 시 누락을 발견하는 관리 기준에 집중했다.

| 대상 | 발견 사항 | 적용한 관리 방식 |
| --- | --- | --- |
| 미디어 형식·출력 | MIME, 허용 형식, 인코더 인자가 여러 파일에 분산 | `src/shared/media.ts`의 동결 메타데이터와 파생 타입. 실제 파일 MIME과 처리 출력 MIME은 구분 |
| 화면 문구 | 상태·검사·준비 단계 문구가 렌더 함수 안에 분산 | `src/local/labels.ts`의 타입으로 검사하는 상태별 문구. 변경 없는 화면 재사용은 유지 |
| 파일명 | 다운로드 모듈이 확대 정책에 있는 이름 정리 함수에 의존 | 의존성 없는 `src/shared/filename.ts`로 이동. 기존 policy export도 유지 |
| 백신 연결 | 상태 조회와 파일 검사의 연결·응답·타임아웃·종료 처리 중복 | 내부 `nativeRequest<T>`와 프로토콜 메타데이터. 제한 시간·문구·응답 검증·권한 순서·잠금·중복 조회 병합 유지 |
| 다운로드 상태 | 상태 타입·검사 목록·진행 상태 판정 중복 | 상태 목록에서 타입을 파생하고 공통 활성 상태 판정 사용 |
| 메시지 라우터 | 재감지와 목록 작성이 긴 중첩 분기 안에 포함 | 비공개 함수로 추출. 신뢰할 수 있는 UI 검사 뒤 호출하며 티켓·탭 변경 검증 유지 |
| DB 트랜잭션 | 시작 오류 처리와 기존 guarded 처리 중복 | 기존 guarded 경로 재사용. 스키마·이전 표시·복구·시크릿 보존 규칙은 유지 |
| 배포 번들 | `hardening/service.js`는 실제 앱이 참조하지 않는 독립 테스트 진입점 | 설치본에서 제외. 같은 production 모듈을 브라우저 fixture로 빌드하여 검사 |
| 예전 네트워크 API | `fetchManifest()`는 테스트에서만 호출하는 text 래퍼 | 성공 응답 URL도 제공하는 기존 `fetchManifestResource()`로 통일 |
| 빌드 정보 | 진입점·복사 파일·벤치마크 목록이 스크립트에 분산 | `scripts/project.mjs`의 동결 카탈로그. 빌드 보고서에 진입점별 입력 모듈·바이트 기록 |
| 해시·파일 목록 | 빌드·측정·패키징의 순회 및 해시 코드 중복 | 공통 artifacts 헬퍼와 명시적 캐시 제외 정책. 정렬·직렬화 계약 유지, 링크·특수 파일 거부 |
| ZIP 작성기 | JavaScript 문자열 속 Python 코드이며 테스트도 정규식으로 추출 | `scripts/archive.py`로 분리. 테스트가 실제 작성기를 직접 읽어 실행 |

## 유지한 동작과 검사 범위

형식 검증의 기존 문자열 변환 동작, FFmpeg 인자 전체 순서, 출력 코덱·비트레이트·트랙 선택과 파일명을 유지한다. 변경 가능한 결과 인자 배열은 요청마다 새로 만들고 공통 프로필은 동결한다. 메타데이터 검사에는 명령 전체 비교와 수정 시도에 대한 회귀 검사가 포함된다.

Windows 전용 동적 로딩·레지스트리·AMSI, 검사 실패/미검사 처리, DB 복구·이전·시크릿 격리, HTTP/3 늦은 관측과 비유한 화질 정보 대체 경로는 실제 필요한 분기다. 일반 성공 경로에서 실행되지 않는다는 이유로 삭제하지 않았다. 서로 목적이 다른 파일·스트림·큐·백신 용량 한도도 합치지 않았다. Python 네이티브 소스는 변경하지 않는다.

소스 감사는 런타임 TypeScript import와 manifest·HTML·Worker·명시적 외부 모듈을 검사하며 제품 코드를 실행하지 않는다. 미참조 모듈과 런타임 순환을 거부하고 타입 선언은 구분한다. 모든 동적 실행·네이티브 코드의 미사용 여부를 자동으로 증명하는 도구는 아니다. `treeIdentity`의 선택적 파일 목록은 내부 `files()` 결과를 받는 용도다.

공통 해시는 기존 `경로 + NUL + 내용 SHA256`의 정렬된 직렬화 방식을 유지한다. 소스 검사에는 새 도구와 타입 선언, 비교 fixture, `tsconfig.json`도 포함한다. 배포 파일 해시는 HTML·CSS·이미지·라이브러리·설치 문서를 포함한다.

코드 줄 수 감소를 개선의 기준으로 삼지 않았다. 메타데이터와 감사 코드는 추가되지만 중복 배포 번들을 제거하고 변경 위치·검증 규칙을 명확히 한다. `reports/performance*.json`의 기존 알고리즘 기준 비교는 회귀 검증이며 이번 리팩토링 자체의 다운로드·인코딩 가속 배수가 아니다.

최종 실행 결과는 `reports/release-validation.json`, 구조는 `reports/source-audit.json`, 실제 배포 구성과 크기는 `reports/build.json`에서 확인한다. Chrome API 테스트 대역과 Linux에서 Windows API를 직접 실행하지 못하는 기존 검증 한계는 유지한다.

## 최종 측정·검증

| 지표 | 1.9.0 기준 | 1.9.1 결과 |
| --- | --- | --- |
| 압축 전 앱 JavaScript(FFmpeg 제외) | 316,521바이트 | 292,229바이트(-24,292, 약 7.67%) |
| 배포된 앱 JS 번들(FFmpeg 제외) | 9개 | 8개 |
| 전체 통합 검증 | 기존 121개 단위 검사 | 150개 단위·48개 네이티브·77개 브라우저 통과 |
| 추가 검증 | 기존 기준 유지 | 구조 감사·알고리즘 5개·실제 HTTP/3 4개 통과 |

독립 검토 에이전트가 직접 배포 해시와 실제 파일 크기를 재계산했다. FFmpeg 바이너리·해시와 기능 목록은 유지됐다. 검증 결과의 현재 소스·빌드 일치를 확인한 뒤 배포 ZIP을 생성한다.
