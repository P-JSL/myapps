# Windows 직접 실행 검사 계획

대상은 현재 초안의 Windows 앱과 MissAV Chrome 확장이다. 현재 연결된 실행 컴퓨터는 Linux이며 연결된 Windows 원격 세션은 없다. Linux 실행이나 이전 CI 결과를 새 Windows 실행으로 표시하지 않는다.

Windows 앱 코드에서 일반 CDN의 정상 HLS 미디어 재생목록을 웹페이지로 오인해 거부하는 문제를 로컬 고정 버전의 yt-dlp로 재현했다. 직접 주소의 실제 HLS 본문을 확인하는 수정과 암호화·라이브·가짜 HTML 거부 검사를 추가했다. 이 변경의 Windows 네이티브 검증은 아직 실행하지 않았다.

검증 전용 워크플로 `.github/workflows/verify-windows.yml`은 `windows-2025`에서 현재 초안을 새로 빌드하고, ZIP을 한글과 공백이 포함된 경로에 풀어 내장 Python·Qt·FFmpeg로 실행한다. 준비된 검사는 직접 HLS 회귀, MissAV 통신, 실제 설치된 Chrome 확장의 다운로드·재시도와 Windows 네이티브 GUI 검사 7개다. 실제 EXE 실행·다운로드 버튼 조작·403 후 재시도·취소 후 재시도·한글 경로 저장·영상 및 음성 확인·자원 반환을 확인하고 화면을 기록한다. 엔진·분리된 메타데이터 작업기를 교체하지 않으며, 테스트용 HTTPS 터널은 외부 인터넷으로 전달하지 않는다.

워크플로는 수동 실행만 허용하며 저장소 권한은 `contents: read`이다. 릴리즈 생성·수정, 사이트 배포, 환경 게시 단계를 포함하지 않는다. 검사 결과와 화면만 비공개 CI 아티팩트로 보관한다. Windows 빌드 ZIP은 릴리즈나 아티팩트로 게시하지 않는다.

사용자가 `codex/windows-verify-20261117` 브랜치 업로드와 Windows CI 실행을 명시적으로 허용했다. 기존 등록된 워크플로 경로를 이 검증 브랜치에서만 읽기 전용 내용으로 바꿔 수동 실행한다. main·기존 태그·릴리즈·환경은 변경하지 않는다.
