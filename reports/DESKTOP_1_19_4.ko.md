# 1.19.4: 1.18 다운로드 경로 복원·로그 유지

**요청에 따라 다운로드의 기준을 v1.18.0으로 되돌렸습니다.** 영상·음성을 기존 yt-dlp 다운로드 경로로 순서대로 받고 검사·FFmpeg 병합·최종 저장을 수행합니다. 기존 v1.18.0 태그는 이동하지 않고 수정본을 1.19.4로 배포합니다.

## 유지·복원 범위

| 항목 | 동작 |
| --- | --- |
| 다운로드 | v1.18의 `YoutubeDL.dl`을 모든 트랙에 사용. 1.19 네이티브 전송기·HTTP/3·직접 파일 Range 분할·중간 호환 경로 전환 제거 |
| 동시성 | v1.18의 최대 16개 작업·사이트별 제한·조각 병렬 예산·분석/변환/검사 자원 제한 유지 |
| 설정·런타임 | v1.18 설정과 고정된 7개 런타임 입력 복원. 네이티브 전송 전용 모듈·추가 라이브러리·속도 제한 기능 제거 |

## 속도 개선의 범위

기존 v1.18은 영상과 음성 트랙마다 `YoutubeDL`을 새로 만들었습니다. 복원본은 **한 다운로드 작업 안에서 클라이언트 1개를 재사용**합니다. 트랙의 순차 다운로드와 FFmpeg 처리 순서는 유지하고, 트랙별 조각 작업 수와 자원 임대도 그대로 적용합니다. 다른 작업과 클라이언트·쿠키 상태를 공유하지 않습니다.

고정 yt-dlp 2026.10.21 소스의 `YoutubeDL.dl`은 호출마다 트랙용 FileDownloader를 새로 구성하고 조각 작업을 끝낸 뒤 반환합니다. 따라서 트랙 사이에 `concurrent_fragment_downloads`만 갱신할 수 있습니다. 재사용으로 추출기·요청 처리기·opener·SSL 컨텍스트의 중복 초기화를 줄입니다. 두 트랙 작업에서 클라이언트 생성 횟수가 2회에서 1회로 줄며, 실제 인터넷 다운로드 속도 증가율을 측정했다는 뜻은 아닙니다.

이전 재시도 로그 콜백이 yt-dlp의 `n=` 키워드 호출과 맞지 않던 부분도 고쳤습니다. v1.18의 기본값처럼 추가 대기 없이 제한된 재시도를 수행하며 시도 번호·취소는 계속 기록합니다. FFmpeg의 기존 스트림 복사와 화면/로그 진행률 갱신 간격은 유지합니다.

참고 소스: [고정 yt-dlp의 YoutubeDL](https://github.com/yt-dlp/yt-dlp/blob/2026.10.21/yt_dlp/YoutubeDL.py), [기본 FileDownloader](https://github.com/yt-dlp/yt-dlp/blob/2026.10.21/yt_dlp/downloader/common.py), [조각 다운로드](https://github.com/yt-dlp/yt-dlp/blob/2026.10.21/yt_dlp/downloader/fragment.py). 검토에는 해시를 확인한 같은 버전의 캐시 wheel을 사용했습니다.

## 이전 임시 파일과 업데이트

**ZIP 전체를 새 폴더에 압축 해제하고 실행하세요.** 이전 설치 폴더에 덮어쓰면 제거한 추가 런타임이 남을 수 있습니다. 사용자 데이터와 다운로드 파일 위치는 바꾸지 않습니다.

1.19 네이티브 전송의 미완료 파일은 최종 트랙 이름으로 남을 수 있고, yt-dlp는 같은 이름의 파일을 완료본으로 판단할 수 있습니다. 따라서 출처를 증명할 수 없는 이전 임시 트랙은 한 번 다시 받습니다. 사용자 최종 파일이나 소유권이 다른 경로를 지우지 않으며 일반 `.part`·이어받기 상태는 보존합니다. 새 복원 경로임이 표시된 같은 작업의 이후 재시도에서는 v1.18의 완료 트랙 재사용을 유지합니다.

## 검사 범위

**사용자 요청에 따라 이전 전체 검사는 건너뜁니다.** 새 검사는 순차 영상·음성 다운로드, 클라이언트 재사용·작업 간 분리, 트랙별 조각 제한, 설정·임시 파일 전환, 로그·취소·실패·GUI·배포 증거를 확인합니다. 실제 yt-dlp와 FFmpeg로 자체 로컬 영상·음성을 내려받고 병합하며 원본 영상·음성 스트림의 해시와 코덱을 비교합니다.

로컬에서 새 복원·실제 다운로드 검사 14개, GUI·로그 유지 검사 11개, 배포 범위 검사 21개, 총 46개가 통과했습니다. 실제 다운로드 검사는 서로 독립적인 두 작업을 실행해 영상·음성 트랙을 끝까지 받으며 스트림 해시와 코덱을 보존하는지 확인합니다. 클라이언트 생성 횟수와 동시 작업 분리는 별도 검사합니다.

패키징 검사는 제거 대상의 최상위 설치 패키지와 확장 라이브러리를 구분합니다. v1.18의 고정 Python에 원래 들어 있는 pip 내부 인증서·라이선스는 유지하고, 추가했던 최상위 네이티브 전송 라이브러리는 제외합니다. 고정 런타임 입력 전체의 해시와 실제 압축 파일 목록도 함께 확인합니다.

메타데이터 추출은 통제된 입력이며 실제 YouTube 서버 접근이나 인터넷 속도 비교는 수행하지 않습니다. 로컬 Linux에서는 검증한 순수 Python wheel과 시스템 FFmpeg를 사용하고, Windows 배포 전에는 실제 내장 yt-dlp·FFmpeg로 같은 새 검사를 통과해야 합니다. 원시 결과와 현재 소스/ZIP의 연결은 `release-validation.json`, Windows 결과는 Release의 `WINDOWS-VALIDATION.json`을 기준으로 합니다.
