# MissAV 요청 호환성 개선 · 1.20.0

릴리즈: `v1.20.0-preview.1`. MissAV 포함 Chrome 확장과 Windows 앱을 새로 빌드한다. MissAV 미포함 확장은 기존 v1.19.4 파일을 동일한 SHA-256으로 제공한다. 환경 자체는 게시하지 않는다.

## 확인한 원인과 수정

- 사용자 Chrome에서는 영상이 재생되지만 확장만 403으로 실패했다. 제공된 실제 `surrit.com/.../1080p/video.m3u8`은 일반 요청에서 403 및 Cloudflare 오류 1010을 반환했다. 브라우저 호환 HTTP/2 요청과 재생 사이트 출처를 적용하면 HTTP 200, 유효한 HLS 29,535바이트를 반환했다. TLS 검증과 관리 환경 프록시를 유지했다. curl 라이브러리의 프로토콜 열거값 3은 HTTP/2이며 HTTP/3이 아니다.
- 확장이 실제 관측한 주소의 UUID 대소문자와 중복 슬래시를 바꾸던 문제를 수정했다. 경로와 서명 쿼리를 그대로 유지하며, 실제 요청 주소가 발견되면 같은 영상의 추측 주소와 오래된 스크립트 주소를 제거한다.
- 확장 다운로드는 사용자가 선택한 작업 ID·원래 탭·영상 UUID에 한정해 콘텐츠 스크립트에서 요청한다. 브라우저가 원래 페이지의 출처·리퍼러·CORS를 적용한다. 재생목록과 모든 영상 조각에 같은 경로를 사용한다. 탭을 닫거나 이동하면 실패하며 원래 탭을 유지하라는 안내를 표시한다.
- 요청 중계는 최대 128 KiB 메시지와 소비자 요청에 따른 읽기를 사용한다. 원본 응답 전체를 메시지나 메모리에 누적하지 않는다. 취소 시 실제 요청도 중단한다. 쿠키·인증 헤더는 중계하거나 추출하지 않는다. 다른 영상 UUID·임의 호스트·HTTP·비표준 포트는 거부한다.
- Windows 앱은 MissAV 페이지의 명시적 HLS 주소와 알려진 플레이어 형식을 인식한다. 실제 JS를 실행하거나 무관한 UUID를 영상으로 추정하지 않는다. 페이지 인증이 실패하면 Chrome에서 감지한 최신 m3u8 주소를 입력하도록 안내한다.
- Windows의 새 통신 처리는 MissAV 작업에만 설치한다. HTTP/2 호환 요청·사이트 출처를 재생목록과 조각에 적용하며, 주소 이동도 같은 영상의 허용 CDN으로 제한한다. 일반 YouTube·직접 주소 작업에서는 추가 라이브러리의 자동 핸들러 등록까지 제외해 기존 요청 핸들러를 유지한다. 기존 yt-dlp 조각 다운로드·취소·이어받기·FFmpeg 병합·검사·로그·최대 16개 동시 작업을 사용한다.
- 인증 HTML을 미디어로 저장하지 않는다. 암호화·DRM·라이브 재생목록을 거부하며 누락된 조각을 건너뛰고 완료로 표시하지 않는다.

## 참고 저장소

`nerdnam/missav-dlp-web`, 확인 커밋 `77f91d10acaab7076bb11fdd7f7ec801769923fb`의 동작과 요청 방식을 조사했다. 공개 라이선스 파일이 없어 해당 구현을 복사하지 않고 독립적으로 구현했다. Flask 서버·쿠키 설정 API·DPI 프로그램·VPN은 추가하지 않았다. CAPTCHA 자동 해결과 브라우저 쿠키 추출도 추가하지 않았다.

새 의존성은 curl-cffi 0.16.3, cffi 2.1.1, certifi 2026.10.19, pycparser 3.12를 버전·다운로드 크기·SHA-256으로 고정했다. 현재 yt-dlp는 curl-cffi 0.17 미만을 요구하므로 0.17을 사용하지 않는다. 원래 휠의 라이선스·메타데이터를 Windows 패키지에 보존한다.

원래 BtbN FFmpeg 배포 URL이 만료되어 새 버전으로 바꾸지 않고, SHA-256으로 고정한 기존 정식 v1.19.4 ZIP에서 동일한 FFmpeg·ffprobe·라이선스와 변경 없는 런처를 사용한다. ZIP 및 개별 파일 해시·기존 매니페스트의 원본 버전을 검사한다. 이 출처는 `desktop/dependencies-lock.json`의 `originalArchive`에 기록한다.

## 집중 검증

이전 전체 검사 묶음은 사용자의 기존 요청에 따라 반복하지 않는다. 변경 범위에 필요한 검사는 다음과 같다.

| 검사 | 범위 |
| --- | --- |
| TypeScript·소스 정책 | 컴파일, 배포 진입점·모듈 정책 |
| Chrome 단위/통합 검사 24개 | 주소 보존·선택 우선순위, 미포함판 원본 파일 동일성, 감지, 요청 중계의 스트리밍·취소·범위·실패 상태 |
| 실제 브라우저 검사 4개 | 서로 다른 페이지 출처로 403 재현, 원래 페이지 요청으로 실제 배포용 offscreen/Worker/WASM/OPFS를 통한 MP4·MP3 저장, MP4의 모든 디코딩 영상 프레임 해시 일치, 인증 HTML 거부 |
| 데스크톱 검사 11개 | 플레이어 파싱·안전한 주소 범위, 실제 TLS/HTTP/2·헤더·재생목록·영상 조각, 화질 선택, 직접 HLS 인식, 기존 일반 핸들러 보존, 자체 영상의 다운로드→FFmpeg 병합 및 영상·음성 검사, 조각 누락 시 실패 |
| 릴리즈 검사 5개 | CI 커밋 제한, 게시된 릴리즈·태그 보존, ZIP 경로, 기존 파일 해시, 버전 고정 |
| Windows 네이티브 화면 검사 1개 | 패키지의 Python·Qt로 실제 창 생성, MissAV 주소 안내와 입력 확인, 의도하지 않은 다운로드가 시작되지 않음 |

Windows CI는 배포 ZIP을 직접 압축 해제해 포함된 Python·curl-cffi DLL·Qt·FFmpeg로 데스크톱 11개와 화면 1개를 실행한다. 브라우저 검사도 같은 커밋의 빌드로 실행한다. 모든 검사와 설치 ZIP의 파일별 해시·소스 일치 검사를 통과한 뒤에만 릴리즈를 공개한다. 결과는 첨부 `WINDOWS-VALIDATION.json`, `BROWSER-VALIDATION.json`, `RELEASE-CONTENTS.json`, `SHA256SUMS-RELEASE.txt`에 기록한다.

실제 사이트 재생목록 요청·형식 인식까지만 확인했다. 실제 사이트 영상 전체 다운로드, 사용자 Chrome의 실제 확장 설치와 사용 환경은 미검증이다. 관리 Chrome의 확장 설치 차단 때문에 브라우저 검사에서는 Chrome 메시지 포트에 테스트 대역을 사용한다. 네트워크의 출처/CORS, 배포용 처리 모듈, Worker·WASM·OPFS와 출력 미디어 검사는 실제 브라우저에서 실행한다. Cloudflare 사람 확인이 필요한 페이지가 데스크톱에서 항상 열리는 것으로 주장하지 않는다.
