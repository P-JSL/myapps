# Video Download Helper 10.6.1.2 분석 및 재작성 범위

## 입력과 구조

- 입력 SHA-256: `705182c167510a908243295819766d9d725db0f1dc84617015ce9331663ec4cc`
- 81개 파일, 압축 해제 크기 14,184,738바이트.
- Chrome Manifest V3, ES module 서비스 워커, offscreen factory, 다운로드 워커.
- 32개 JavaScript 번들, 1개 MJS, 2개 Wasm, 6개 HTML, 33개 언어 리소스.
- TypeScript 원본·소스맵·빌드 프로젝트·원본 테스트·전체 의존성 lockfile은 제공되지 않음.

## 기능

서비스 워커는 네트워크 요청/탐색 관찰, 미디어 발견/상태/설정, 다운로드 큐,
다운로드 API, 알림, 컨텍스트 메뉴, 사이트별 기본 동작과 단축키를 관리한다.
사이트별 isolated/main-world 스크립트가 YouTube, Vimeo, Facebook/Instagram,
VK, Bilibili, iQ 등에서 미디어 정보·플레이어 설정을 읽는다.
offscreen 문서가 다운로드 워커를 만들고 libav.js/FFmpeg Wasm으로 HLS/DASH,
오디오/영상 병합과 MP3 작업을 수행한다. QuickJS Wasm은 YouTube 쪽 JavaScript
평가에 쓰인다. UI는 팝업/사이드바, 기록, 상세, 스마트 이름짓기를 제공한다.
구독 활성화·검증·원격 동작 규칙은 원본 서비스와 연결되어 있다.

## 언어 선택과 호환성

TypeScript를 선택했다. 브라우저 확장 API와 JavaScript 실행 모델을 그대로
사용하면서 메시지 스키마, 상태, 미디어 한도와 작업 수명을 명시적으로 검사할 수 있다.
Rust/Wasm으로 UI와 확장 API 전체를 옮기면 별도 JS 브리지와 빌드 체인이 필요하고
호환성 검증 범위가 커진다. 언어 변경만으로 보안이나 속도가 보장되지는 않는다.

이번 결과는 **전체 엔진의 독립적인 완전 재작성물이 아니다.** 원본 엔진을 보존하고
복원 가능한 YouTube/Vimeo/iQ/Bilibili/Javrank/Taiav 브리지, 메시지 검증,
업스케일링·임시 저장·UI를 엄격한 TypeScript로 재작성/추가한 호환성 중심의 버전이다.
원본 개발 소스 없이 7MB에 가까운 압축 번들과 외부 사이트·구독 서비스 전체를
새 엔진으로 대체하면서 기능/결과의 완전 동일성을 입증할 수 없다.
보존 파일과 변경 파일의 SHA-256 비교는 `reports/build.json`에 기록한다.

## 권한 및 신뢰 경계

기존 `<all_urls>`, tabs, webRequest, webNavigation, scripting,
declarativeNetRequest, downloads, storage, notifications, sidePanel, offscreen,
unlimitedStorage 등의 권한은 원본 사이트 지원을 위해 유지한다. 새 권한은 추가하지 않는다.
MAIN world와 페이지는 같은 신뢰 영역이다. 예측 가능한 BroadcastChannel 이름은
인증 수단이 아니다. 수신 스키마 검증은 오류/과도한 데이터와 잘못된 명령을 줄이지만
사이트 자체가 거짓 플레이어 정보를 제공하는 것을 막을 수 없다.

## 보안 변경

- 서비스 메시지의 채널·크기·깊이·타입·sender.id·sender.url을 검증한다.
- 확장 UI 명령은 같은 확장 페이지에서만 허용한다.
- 활성화는 기존 활성화 페이지에, QuickJS 요청은 YouTube에 제한한다.
- VK 서비스 대리 요청은 원래 사용하던 HTTPS POST 목적지만 허용한다.
- QuickJS의 처리 시간·힙·스택을 제한한다. 권한/유료 기능 판정은 수정하지 않는다.
- 6개 isolated 브리지 수신 경계에 검증을 삽입한다. 빌드 시 패치 위치가 정확히
  하나인지 검사하고 원본 해시가 달라지면 빌드를 중단한다.
- 새 화면은 별도 CSP, textContent 렌더링, 원격 통신 없는 로컬 Worker를 사용한다.
- 원본 전체의 CSP에는 object-src/base-uri 제한만 추가해 기존 이미지/통신을 유지한다.
- 복사 큐는 origin-wide Web Lock으로 직렬화하고 UUID 이름, TTL, 용량/개수 제한을 쓴다.
- 의도적인 보안 한도는 원본보다 큰 메시지/장시간 스크립트를 거부할 수 있다.
  따라서 악성·비정상 입력까지 원본과 동일하게 처리한다고 주장하지 않는다.

## 업스케일링

다운로드가 성공한 뒤 원본 내부 파일이 정리되기 전에 지원 파일을 제한된 큐에
복사한다. 완료 알림의 버튼 또는 확장 옵션/아이콘 우클릭 메뉴에서 작업을 선택한다.
실제 확대와 저장은 사용자가 명시적으로 실행한다. 원본 파일은 덮어쓰지 않는다.
알림이 꺼져 있으면 옵션의 완료 목록에서 선택할 수 있다.

Lanczos 2x/4x 보간이며 AI 초해상도 모델은 포함하지 않는다. 이미지는 PNG,
동영상은 MP4(H.264/AAC)로 새로 인코딩한다. 새 결과의 바이트/코덱/메타데이터는
원본과 같지 않다. 원래 다운로드 파일과 기본 동작의 보존이 호환성 목표다.
원본 libav 바이너리는 영상 인코더가 없으므로 추가 FFmpeg core를 로컬로 제공한다.

한도: 입력/출력 256MiB, 큐 총 512MiB·4개, 복사본 TTL 24시간(다음 사용/시작 시 정리),
영상 10분, 결과 16,777,216픽셀·한 변 8,192, 실행 5분. 시크릿 파일은 큐에 넣지 않는다.
브라우저 탭을 닫거나 취소하면 Worker를 종료한다. 탭을 열어 두어야 작업이 유지된다.
오디오 다중 트랙은 가능한 경우 AAC로 변환하지만 자막·첨부·모든 메타데이터 보존은
새 업스케일 결과의 보장 범위가 아니다. 원본 다운로드 파일은 별도로 남는다.

## 검증 범위와 남는 한계

자동 검증은 타입 검사, 입력/권한/한도 회귀 테스트, 원본 브리지와 결과 비교,
실제 Chromium 확장 로드/화면/로컬 미디어 다운로드 및 업스케일링을 대상으로 한다.
실행 결과와 실패/미실행 항목은 `reports/VALIDATION.ko.md`를 확인한다.
사용자 계정·유료 구독·지역 제한·실시간 사이트 변경을 포함한 전체 사이트 동등성은
검증되지 않았다. Firefox/Safari 대응을 새로 추가하지 않으며 원본의 Chrome MV3
호환 범위를 기준으로 한다. 전면 교체를 위해서는 원본 개발 소스 및 실제 사이트
회귀 자료가 추가로 필요하다.
