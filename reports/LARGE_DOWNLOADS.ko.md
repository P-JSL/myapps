# My Video App 1.13.0 · 대용량·병렬 다운로드

**기가바이트 단위의 원본 영상을 디스크에 준비하고, 최종적으로 하나의 파일로 저장한다.** 원본 다운로드에는 고정 재생 길이·파일 총용량·전체 5분 제한을 두지 않는다. 실제 저장 가능 범위는 서버 응답, 브라우저 파일 주소 범위와 임시 저장소 할당량, 디스크 여유 공간에 따라 달라진다.

## 사용 방법

기존과 같이 확장 팝업이나 전체 앱에서 **다운로드**를 누른다. 구간 분할·병렬 전송·최종 결합은 자동이며 별도의 수동 병합 단계는 없다. **기록**에서 단계·진행률·수신량을 확인하고 취소할 수 있다. 네트워크 연결 방식은 Chrome이 HTTP/1.1·HTTP/2·HTTP/3 중 협상한다.

| 원본 유형 | 전송·저장 방법 |
| --- | --- |
| 일반 HTTP(S) 파일 | 조건이 맞으면 최대 4개 연결로 4MiB 구간을 병렬 수신하고 OPFS 파일의 정확한 위치에 기록 |
| 구간 지원·버전 식별자가 없는 일반 파일 | 한 번의 전체 200 응답을 작은 조각으로 받아 순차 기록 |
| 완료형 비암호화 HLS·정적 단일 Period DASH | 최대 4개 자산을 병렬 수신한 뒤 디스크 기반 FFmpeg에서 코덱 복사·MP4 병합 |

저장 결과는 일반 파일의 실제 형식 또는 스트림의 단일 MP4이다. HTML 오류 페이지·일반 텍스트를 영상으로 저장하지 않으며 DRM·라이브·사이트 접근 제한 우회는 추가하지 않는다.

## 구간이 섞이거나 잘린 파일 방지

일반 파일은 작은 첫 범위 응답에서 실제 미디어 시작 구조와 총길이를 확인한다. 병렬 전송에는 정확한 206 범위 응답과 **강한 ETag**가 필요하다. 각 후속 구간의 Content-Range·길이·총크기·ETag·최종 URL을 대조하고 If-Range를 사용한다. 응답이 변경되거나 잘못된 범위가 오면 기존 조각과 섞어 성공 처리하지 않는다. 서버가 조건을 제공하지 않으면 순차 전송을 사용한다.

병렬 구간은 원래 파일의 위치에 쓰므로 완료 순서가 달라도 바이트 순서를 유지한다. 실패·취소·저장 공간 오류는 다른 요청도 중단하고 앱의 부분 임시 파일을 정리한다. 재시도는 제한된 일시 오류에 적용하며 이미 검증한 것처럼 불완전한 응답을 등록하지 않는다. **브라우저 종료 후의 자동 구간 이어받기는 제공하지 않는다.** 기록의 다시 시도는 새 작업이다.

HLS/DASH에서 여러 바이트 범위 자산이 같은 최종 URL의 한 파일을 참조하면, 각 응답의 강한 ETag와 Content-Range 총길이가 일치해야 한다. 이 경우 버전 식별자가 없으면 서로 다른 파일 버전의 범위를 섞지 않도록 중단한다. 한 번만 읽는 범위에는 강한 ETag를 요구하지 않는다. 일반 파일에서 식별자가 없어 순차 전송하는 경로와는 구분한다.

## 메모리에 전체 영상을 모으지 않는 병합

HLS/DASH는 원본 자산을 한 OPFS 컨테이너에 기록하고 자산별 위치 색인을 만든다. 여러 트랙·DASH 자산 연결도 위치 색인을 이용한다. FFmpeg의 가상 파일 시스템은 이 디스크에서 필요한 바이트를 읽고 별도 출력 파일에 기록하므로 입력 전체·연결한 트랙 전체·출력 전체를 MEMFS에 복사하지 않는다. MP4의 faststart 처리에 필요한 파일 탐색도 디스크 경로를 사용한다.

네트워크 버퍼와 검사 블록은 제한된 크기로 유지한다. 이 설계는 모든 브라우저 메모리 사용량을 일정한 수치로 보장하는 것은 아니다. FFmpeg 엔진과 미디어의 트랙·프레임 색인, 목록 메타데이터도 메모리를 사용한다.

## 남아 있는 자원 조건

| 항목 | 적용 조건 |
| --- | --- |
| 원본 파일·영상 길이 | 별도의 고정 총용량·재생 길이·전체 준비 시간 제한 없음. 안전한 정수 주소·브라우저·서버·저장 공간 조건 적용 |
| HLS/DASH 목록 | 원본 경로는 목록 8MiB·최대 100,000개 자산의 분석 예산 적용 |
| 네트워크 정지 | 응답이 멈춘 요청에는 대기 제한·재시도 정책 적용. 정상 진행 중인 긴 전송을 전체 시간만으로 중단하지 않음 |
| 디스크 공간 | 수신 조각·병합 출력·Chrome에 저장한 파일이 한동안 함께 존재할 수 있음 |
| 준비 대기열 | 최대 8개. 무거운 준비는 순차 실행하며 각 작업 내부에서 병렬 수신 |
| MP3/M4A 다운로드 변환 | 기존 메모리 경로의 입력 128MiB·출력 약 128MiB 미만·4,096조각·준비 5분 유지 |
| 로컬 확대·변환·병합 | 별도 미디어 도구의 10분 길이·5분 처리 및 기존 크기·픽셀 한도 유지 |

**긴 영상을 다운로드할 수 있어도 자동 확대·변환까지 같은 크기로 수행하는 것은 아니다.** 확대용 복사 큐는 기존 파일당 256MiB·총 512MiB·4개·24시간 정책을 유지한다. 원본 파일의 디스크 준비를 사용할 수 없을 때 지원되는 경우 Chrome 직접 다운로드로 전환할 수 있으며, 스트림 병합 실패나 위험 입력 차단을 원본 직접 저장으로 우회하지 않는다.

## 검사 결과의 의미

256MiB를 넘는 최종 파일의 전체 SHA-256은 4MiB 이하 읽기로 계산한다. 작은 준비 결과의 기존 전체 정적 검사는 유지하고,256MiB를 넘는 파일은 정적 검사 범위를 8MiB 접두부로 제한하여 미완료 범위를 표시한다. 해시는 파일 동일성 확인이며 안전 판정이 아니다.

스트림 입력은 디코딩 전에 블록·중첩 구간·DASH 경계의 제한된 정적 규칙을 검사한다. 이 검사는 완전한 악성코드 검사나 모든 구조·조각 경계 탐지를 보장하지 않는다. 위험 신호가 있으면 기존 확인·자동 처리 차단 규칙을 유지한다.

외부 백신·도우미는 별도 한도를 따른다. 현재 도우미의 내부/Defender·ClamAV 파일 크기 범위는 2GiB−1바이트이며 Windows AMSI는 128MiB까지다. 더 큰 파일을 내려받을 수 있어도 백신이 검사하지 못하면 **미검사·확인 대기**로 남기며 위협 미탐지로 바꾸지 않는다. 백신 연동 OFF는 앱의 도우미 호출만 중단하고 OS·Chrome 보호는 유지한다. 백신의 정상 확인 없이 자동 확대를 제안하지 않는다.

## 검증 범위

현재 실행의 결과·빌드 식별자는 `large-download.json`, `browser.json`, `release-validation.json`에 기록한다. 대용량 시험은 소유한 짧은 MP4에 큰 free 영역을 넣어 구간·오프셋·저장·해시를 확인하고, 긴 타임스탬프 입력으로 재생 길이 기준의 차단 여부를 확인한다. 이것이 모든 사이트·코덱·장시간 실제 촬영본의 호환성이나 일정한 속도를 보장하는 것은 아니다.

브라우저 하네스의 실제 파일·Worker·Wasm·OPFS 동작과 Chrome 확장 API 대역을 구분한다. 관리자 정책에 따른 실제 확장 설치 및 Windows 백신 실기기 검증의 기존 한계는 유지한다. 상세 백신 조건은 `SECURITY_DOWNLOADS.ko.md`, 내부 검사 범위는 `INTERNAL_SCAN.ko.md`를 참고한다.

확장은 기존 `unlimitedStorage` 권한을 유지하며 이 변경에서 새 권한을 추가하지 않는다. 로컬 HTTP 시험 페이지는 설치된 확장의 저장소 예외를 갖지 않으므로, 대용량 브라우저 시험에만 CDP로 8GiB 할당량을 지정한다. 이는 폐기할 시험 컨텍스트의 조건이며 운영체제·제품·사용자 프로필의 저장 설정을 바꾸는 기능은 아니다. 이 시험 조건으로 모든 사용자 환경의 가용 용량을 보장하지 않는다.
