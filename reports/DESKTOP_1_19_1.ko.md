## 확인한 원인과 한계

제보 영상 ID는 `LghCA95RphM`이다. 제보된 화면은 영상 수신 뒤 약 94%에서 실패하고, 임시 폴더에는 `owner.json`, `selection.json`, `source-0.mp4`만 남아 있었다. 저장 공간이 부족하다는 증거는 없었다.

실제 Engine·transfer·SQLite 흐름에 영상 1,610,000바이트와 오디오 96,000바이트를 제공하면 영상 수신 뒤 **94.37%**가 된다. 다음 오디오 요청을 거절하면 기존 버전의 일반 오류 문구가 그대로 재현된다. 실제 네이티브 클라이언트와 루프백 서버의 별도 원인 조사에서도 영상 뒤 오디오 거절로 약 94.9% 실패가 재현됐다. 영상·오디오가 정상 응답할 때 공유 연결 풀 자체는 끝까지 완료됐다.

확인된 코드 결함은 안전하게 분류한 `TransferError`가 엔진에서 일반 예외로 처리되어 구체적인 HTTP·연결 오류를 잃고 저장 공간까지 언급하는 문구로 바뀌는 것이었다. 또한 범위 확인 요청만 거절하는 서버에서도 일반 GET을 시도하지 않고 끝났으며, 일부 바이트를 받은 뒤 연결이 끊어지면 기존 호환 다운로더로 복구하지 않았다.

**제보 영상의 실제 서버 응답 코드는 직접 확인하지 못했다.** HTTP 403 또는 특정 프로토콜이 해당 서버의 확정 원인이라고 단정하지 않는다. 이번 패치는 재현된 전송 경계·복구 누락·오류 분류를 수정한 것이다.

## 수정

| 문제 | 변경 |
| --- | --- |
| 범위 확인 거절 | 최초 확인 요청의 HTTP 400·403·405·416은 쓰기 전 일반 GET으로 전환. 일반 GET도 거절되면 HTTP 상태와 오디오/영상 단계를 표시 |
| 일시 연결 중단 | 실패한 네이티브 전송 파일을 안전하게 정리한 뒤 **현재 트랙만 한 번** 기존 다운로더로 복구. 같은 공개 URL·헤더를 사용하고 추가 재시도는 0으로 제한 |
| 기존 영상 재수신 | 같은 영상·형식의 완료된 영상은 유지하고 다시 시도 시 오디오만 수신. 기존 임시 파일이나 외부에서 바뀐 파일을 덮어쓰지 않음 |
| 모호한 오류 | 영상·오디오·검사·병합·저장 단계를 표시. 실제 공간 부족·권한/잠금·긴 경로와 HTTP/연결 실패를 분리. 원본 URL·토큰·라이브러리 진단은 노출하지 않음 |

검증자 변경·범위 불일치 같은 무결성 오류, 사용자의 취소, 파일 오류에는 호환 복구를 적용하지 않는다. 서버의 긴 대기 요청도 우회하지 않는다. TLS·프록시·속도 제한·전역 전송 예산은 그대로 적용한다.
